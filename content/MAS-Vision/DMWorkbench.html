MAS.Vision - DM Workbench

视觉工作台：在画布上用节点搭视觉流程。一张画布可以并存多条相互独立的管道（例如颜色检测和手眼标定）。设计器与运行时的实现见 MAS.VisionFlow

分类

分类 定义
准备（Prepare） 流程起点：图像源、相机
设备输入（DeviceInputs） 从设备读取的数据，如机器位姿
预处理（Preproc） 数据变换：颜色空间转换、ROI（可随动）、滤波去噪、阈值二值化、形态学
定位测量（Locate） 边缘检测、直线定位（找边）、圆定位（找孔）、Blob 分析、特征匹配（可旋转缩放）、ChArUco 角点定位（按 ID 锁定标定板角点）、卡尺（找边 / 边缘对量宽度）、卡尺找线、卡尺找圆（亚像素精测，可随动）；输出原图（直通，供下游继续处理）、定位结果与标注图（只供查看，最后一个端口），多目标节点（圆定位、Blob 分析、卡尺类）另有定位列表输出
几何测量（Geometry） 两点距离（含两圆间隙）、点线距离、两线关系（夹角、交点、平行/垂直）、数值判定、坐标映射（按坐标变换换坐标系）；定位结果当点、当直线（过该点沿其角度）或当圆用，单位跟随输入
集合（Collection） 多目标定位列表：筛选、排序（按行/列、蛇形、按属性、按距离）、取元素、计数判定、合并
执行（Execute） 识别与解算：颜色识别、模板匹配、姿态解算
视觉引导（Guidance） 示教对位（相对基准的 ΔX、ΔY、Δθ）、像素转机械坐标（2D 标定，龙门/XY 平台）、位置补正（拍基准 Mark 求工件的平移与旋转）、手眼坐标转换（相机下目标位姿换算到机器人基座）
资源（Resources） 产出被其他流程消费的资源：相机标定、2D 标定（九点）、手眼标定
扩展（Expanding） 插件型节点，如图像信息
结束（Finish） 流程收尾，如图像浏览器
工具（Tools） 不参与管道执行：位姿生成、脚本执行

常见任务

任务 搭法 要点
定位边缘 图像源/相机 → 滤波去噪（高斯） → 直线定位 期望角度填边的大致方向，角度容差收窄可避开其它边；结果为中点与角度
定位孔位 图像源 → 滤波去噪 → 阈值二值化（大津，暗孔打开反相） → 形态学（开运算） → Blob 分析（最小圆度 0.8） 质心为亚像素精度；孔边缘清晰、背景干净时也可直接用 滤波 → 圆定位
抓特征 场景图像源 + 模板图像源（或 ROI 截取） → 特征匹配 模板需要有纹理与角点；能应对旋转与缩放。纹理少、只有平移时用模板匹配更稳
二维引导 任一定位节点的“定位”输出 → 示教对位 标准位置运行一次后点“设为基准”；填像素当量后按毫米输出 ΔX、ΔY、Δθ
三维引导 相机 → 姿态解算 → 手眼坐标转换（眼在手上时再接机器位姿） 先用手眼标定节点生成资源，再在手眼坐标转换里选中该资源；输出为机器人基座下的目标位姿
龙门打螺丝/点胶（2D） 相机 → 滤波 → 阈值 → Blob 分析（定位列表）→ 列表筛选 → 像素转机械坐标（接机器位姿）→ 列表排序（行蛇形）→ 计数判定 先用 2D 标定（九点，实心圆点 Mark，或复用相机标定的 ChArUco 板：图像源 → ChArUco 角点定位 → 2D 标定）生成资源并示教针尖偏置；换算成机械坐标后再排序，顺序就按机械坐标走
点位整体补正（2D） Mark 定位（两个及以上 Mark 用 Blob/圆定位的列表；单个 Mark 要用能给角度的特征匹配或直线定位）→ 像素转机械坐标 → 位置补正 工件放标准位置运行一次后点“设为基准”；之后每次输出 ΔX、ΔY、Δθ（绕 CenterX、CenterY）与矩阵 A~TY，约定同图纸导入的 RigidTransform，脚本里可直接 RigidTransform.ApplyOffset(new Point(DX, DY), DAngle, new Point(CenterX, CenterY), points)；设最大偏移、最大角度防止异常结果下发
尺寸测量 定位 → 两点距离 / 点线距离 / 两线关系 → 数值判定 先换算成机械坐标即按 mm 判定；两条边的交点可当工件角点
卡尺精测 宽度/间隙：图像源 → 卡尺（边缘对）→ 数值判定（接测量值输出）；孔径：卡尺找圆 → 数值判定（接直径输出）；边距、夹角：两个卡尺找线 → 两线关系 / 点线距离 在设置窗口里框搜索区，调完按标题栏的运行按钮（F5）直接运行到此节点看结果，不用关窗口；箭头为搜索方向，要找的边与箭头垂直，极性按箭头方向看（亮带宽度：暗到亮 + 亮到暗；暗缝反过来）。剖面图上看对比度峰是否越过阈值虚线来调“最小对比度”“平滑 σ”；找线/找圆时橙色点为拟合剔除的离群点（毛刺、缺口）。工件会偏移时把 Mark 定位接到第二个输入“跟随定位”，示教位置运行一次后点“设为跟随基准”，用法同 ROI 随动
ROI 随动 工件定位（Mark、边、特征匹配）→ ROI 选择器第二个输入“跟随定位”；ROI 输出 → 卡尺/差分/定位等精测 → 坐标映射（接 ROI 的变换输出）→ 原图坐标 工件在示教位置运行一次后在 ROI 卡片上点“设为跟随基准”；之后 ROI 随工件平移、旋转，输出与示教时取景一致（当前图按定位反向映射回示教姿态再裁剪，亚像素）。定位没有可靠角度时（圆定位、Blob）取消“跟随旋转”。跟随定位没有结果时管道失败，不会裁到旧位置

单个定位结果可以直接连到列表输入，当作只有一个元素的列表；列表不能直接连到只收单个结果的输入，要用“取元素”明确取第几个。

管道脚本里按“节点标题 + 结果键”取值，例如：

if (result.TryGetValue<double>("示教对位", "DX", out var dx) && result.TryGetValue<double>("示教对位", "DY", out var dy)) {
    // 写回 PLC
}

各节点的结果键可在输出查看窗口的“结果数据”页看到。

编辑

  • 从输出端口拖向输入端口连线，拖动时可连接的端口会高亮，靠近自动吸附；类型不兼容、重复或会成环的连线不允许
  • 单输入端口再接一条线会替换原来的线
  • 框选、Ctrl / Shift 多选，Ctrl+C / Ctrl+X / Ctrl+V / Ctrl+D，Delete 删除，Ctrl+Z / Ctrl+Y 撤销重做，方向键微调
  • 双击标题重命名，双击卡片其他位置打开设置窗口；卡片可折叠
  • 常用参数直接在卡片上改，其余在设置窗口里改；没有属性面板

管道

管道由画布自动划分：每个至少包含两个非工具节点的连通分量就是一条管道，图一变就在后台重建，不需要手动「拓扑」。增删节点后，管道按节点重叠度与原来的管道对应，名称和脚本跟着走。

管道运行中时，它的节点不能删除、不能连线或断线，参数照常可改。

执行顺序

管道内按拓扑排序（Kahn 算法，同层按节点位置排序）确定顺序；执行时入度为 0 的节点先跑，同一批就绪的节点并行执行，某个节点失败则整条管道立即失败，下游不再执行。

B   A
|   |
D   C
 \ /
  E
  |
  F

A、B 并行；C、D 各自在上游完成后执行；E 等 C、D 都完成；最后 F。

节点在第一次触发或启动时按需初始化，结构变化后会重新初始化；也可以在顶部或管道面板里手动初始化。

运行到节点、查看输出

卡片上的运行按钮只执行该节点及其上游；点击输出端口旁的查看按钮可以看端口最近一次的值。节点右上角的状态点和底部的耗时显示最近一次执行结果。

管道脚本

每条管道有一个脚本处理器（IVisionPipelineHandler），启动后按 FixedIntervalMs 循环：

  1. TriggerSignalAsync 返回 true 时执行一次管道（例如读 PLC 触发位）
  2. HandleResultAsync(VisionRunResult) 处理结果（例如写回 PLC）；执行失败时也会先调用它，便于回写 NG，然后循环异常停止
  3. CompleteAsync 结束本轮（例如复位触发位）
public async Task HandleResultAsync(VisionRunResult result, CancellationToken token = default) {
    if (result.TryGetValue<double>("颜色识别", "Score", out var score)) {
        // 按节点标题 + 结果键取值，键名不区分大小写
    }
}

脚本类名由运行时生成，不要修改；构造函数可以注入应用中注册的服务，如 IProtocolManager。
