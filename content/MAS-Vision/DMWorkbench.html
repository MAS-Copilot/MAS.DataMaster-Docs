MAS.Vision - DM Workbench

视觉工作台：在画布上用节点搭视觉流程。一张画布可以并存多条相互独立的管道（例如颜色检测和手眼标定）。设计器与运行时的实现见 MAS.VisionFlow

分类

分类 节点
准备（Prepare） 图像源、相机
设备输入（DeviceInputs） 机器位姿
预处理（Preproc） 颜色空间转换、ROI 选择器（可随动）、滤波去噪、阈值二值化、形态学
几何变换（Transform） 旋转平移、定位转正、透视矫正、缩放、翻转、畸变校正
定位测量（Locate） 边缘检测、直线定位、圆定位、Blob 分析、特征匹配、ChArUco 角点定位、卡尺、卡尺找线、卡尺找圆、形状匹配、模板匹配、颜色识别
几何测量（Geometry） 两点距离、点线距离、两线关系、数值判定、坐标映射
集合（Collection） 列表筛选、排序、取元素、计数判定、合并
视觉引导（Guidance） 示教对位、像素转机械坐标、位置补正、手眼坐标转换、点图移动、姿态解算
资源（Resources） 相机标定、2D 标定、手眼标定
扩展（Expanding） 图像信息
结束（Finish） 图像浏览器
工具（Tools） 位姿生成、脚本执行（不参与管道）

约定：

  • 定位类节点输出原图（直通）、定位结果与标注图；标注图只供查看，是最后一个端口。多目标节点（圆定位、Blob 分析、卡尺类）另有定位列表输出
  • 几何测量把定位结果当点、当直线（过该点沿其角度）或当圆用，单位跟随输入
  • 几何变换节点（透视除外）另有“输出 → 原图”变换输出，接坐标映射可把输出图上的结果换回原图坐标

常见任务

任务 搭法 要点
定位边缘 滤波去噪 → 直线定位 期望角度填边的方向，收窄容差避开其它边
定位孔位 滤波 → 阈值（大津，反相）→ 形态学（开）→ Blob 分析 最小圆度 0.8；背景干净时可直接 滤波 → 圆定位
抓特征 场景图 + 模板图 → 特征匹配 模板要有纹理；只有平移时模板匹配更稳
按轮廓定位 相机 → 形状匹配 设置窗口里框模板区、放参考点、点「学习模板」，再框搜索区；抗旋转、亚像素，模板随工程保存
二维引导 定位 → 示教对位 标准位置运行一次后“设为基准”
三维引导 相机 → 姿态解算 → 手眼坐标转换 先做手眼标定；眼在手上再接机器位姿
龙门打螺丝/点胶 阈值 → Blob 分析 → 列表筛选 → 像素转机械坐标 → 列表排序 → 计数判定 先做 2D 标定并示教针尖偏置；换成机械坐标后再排序
点位整体补正 Mark 定位 → 像素转机械坐标 → 位置补正 标准位置“设为基准”；输出 ΔX、ΔY、Δθ 与矩阵，见下
尺寸测量 定位 → 两点 / 点线 / 两线 → 数值判定 先换机械坐标即按 mm 判定
卡尺精测 卡尺（边缘对）/ 卡尺找圆 → 数值判定 设置窗口里框搜索区，F5 运行看结果，见下
ROI 随动 Mark 定位 → ROI 选择器（跟随定位）→ 精测 → 坐标映射 示教位置“设为跟随基准”；Mark 丢失时管道失败
定位 → 转正 → 精测 定位 → 定位转正（裁剪）→ 精测 → 坐标映射 局部图里目标方向固定，精测参数不受工件放偏影响
斜拍拉正 透视矫正 → 后续流程 图上点 4 个角点，或接 4 个 Mark 的定位列表
先缩小再精测 缩放 → 粗定位 → 坐标映射 → 原图精测 大图提速数倍，映射回原图无半像素偏差
整图畸变校正 畸变校正 → 后续流程 需相机标定的内参资源；连续运行用“重映射”

补充说明：

  • 位置补正：输出的 ΔX、ΔY、Δθ（绕 CenterX、CenterY）与矩阵 A~TY 同图纸导入的 RigidTransform 约定，脚本里可直接 RigidTransform.ApplyOffset(new Point(DX, DY), DAngle, new Point(CenterX, CenterY), points)；设最大偏移、最大角度防止异常结果下发。单个 Mark 要用能给角度的定位（形状匹配、特征匹配、直线定位）
  • 卡尺：箭头为搜索方向，要找的边与箭头垂直，极性沿箭头方向看（亮带宽度：暗到亮 + 亮到暗）。剖面图上看对比度峰是否越过阈值虚线来调“最小对比度”“平滑 σ”；橙色点为拟合剔除的离群点。工件会偏移时把 Mark 定位接到“跟随定位”，用法同 ROI 随动
  • ROI 随动：当前图按定位反向映射回示教姿态再裁剪，输出与示教时取景一致；定位没有可靠角度时（圆、Blob）取消“跟随旋转”
  • 定位转正：整幅图模式加“固定位置”可把每次的工件对齐到同一处（金样差分前的对齐）；边界填充选“复制边缘”不给卡尺造假边
  • 畸变校正：校正后的像素坐标对应新相机矩阵（结果里的 NewFx/NewCx…）；只需校正 Mark 坐标时用 2D 标定里的内参选项更省

单个定位结果可以直接连到列表输入，当作只有一个元素的列表；列表不能直接连到只收单个结果的输入，要用“取元素”明确取第几个。

管道脚本里按“节点标题 + 结果键”取值，例如：

var align = result.GetNode("示教对位");
if (align.TryGetValue<double>("DX", out var dx) && align.TryGetValue<double>("DY", out var dy)) {
    // 写回 PLC；节点本次失败时取不到值，不会把上一次的补正量下发
}

各节点的结果键可在输出查看窗口的“结果数据”页看到。

编辑

  • 从输出端口拖向输入端口连线，拖动时可连接的端口会高亮，靠近自动吸附；类型不兼容、重复或会成环的连线不允许
  • 单输入端口再接一条线会替换原来的线
  • 框选、Ctrl / Shift 多选，Ctrl+C / Ctrl+X / Ctrl+V / Ctrl+D，Delete 删除，Ctrl+Z / Ctrl+Y 撤销重做，方向键微调
  • 双击标题重命名，双击卡片其他位置打开设置窗口；卡片可折叠
  • 常用参数直接在卡片上改，其余在设置窗口里改；没有属性面板

管道

管道由画布自动划分：每个至少包含两个非工具节点的连通分量就是一条管道，图一变就在后台重建，不需要手动「拓扑」。增删节点后，管道的标识（脚本类名由它生成）、名称和脚本跟着节点走：

  • 节点集合与以前某一刻完全相同（撤销、重做、断开又连回）时，还给当时的那条管道
  • 否则由拥有其中节点最多的原管道认领；改过脚本或名称的管道优先于默认管道
  • 暂时凑不成管道（删掉唯一的连线、删掉中间节点、被另一条管道合并）的管道不会丢弃，名称与脚本保留，节点重新连上即恢复；改过脚本或名称、且还有节点在画布上的，保存工程时一并保存
  • 恢复时如果名称已被别的管道占用，自动改名
  • 节点全部删除并保存工程后，这条管道才真正删除

管道运行中时，它的节点不能删除、不能连线或断线，参数照常可改。单次触发、运行到节点时不锁结构，执行中途删掉的节点立刻离开画布，相机等资源等这次执行结束再释放；拿着已脱离管道触发、启动、初始化会被拒绝，不会执行旧的节点。

执行顺序

管道内按拓扑排序（Kahn 算法，同层按节点位置排序）确定顺序；执行时入度为 0 的节点先跑，同一批就绪的节点并行执行，某个节点失败则整条管道立即失败，下游不再执行。

B   A
|   |
D   C
 \ /
  E
  |
  F

A、B 并行；C、D 各自在上游完成后执行；E 等 C、D 都完成；最后 F。

节点在第一次触发或启动时按需初始化，结构变化后会重新初始化；也可以在顶部或管道面板里手动初始化。

运行到节点、查看输出

卡片上的运行按钮只执行该节点及其上游；点击输出端口旁的查看按钮可以看端口最近一次的值。节点右上角的状态点和底部的耗时显示最近一次执行结果。

管道脚本

每条管道有一个脚本处理器（IVisionPipelineHandler），启动后按 FixedIntervalMs 循环：

  1. TriggerSignalAsync 返回 true 时执行一次管道（例如读 PLC 触发位）
  2. HandleResultAsync(VisionRunResult) 处理结果（例如写回 PLC）；执行失败时也会先调用它，便于回写 NG，然后循环异常停止
  3. CompleteAsync 结束本轮（例如复位触发位）
public async Task HandleResultAsync(VisionRunResult result, CancellationToken token = default) {
    if (!result.IsSuccess) {
        // 回写 NG
        return;
    }

    var score = result.GetValue<double>("颜色识别", "Score");
}

按“节点标题 + 结果键”取值，标题与键都不区分大小写：

方法 取不到时
result.GetValue<T>(节点, 键) 抛异常，消息里列出本次结果中的节点或该节点的键，便于发现标题写错、节点改名
result.TryGetValue<T>(节点, 键, out value) 返回 false
result.GetValueOrDefault(节点, 键, 默认值) 返回默认值
result.GetNode(节点) 抛异常；返回的节点结果同样有 GetValue、TryGetValue、GetValueOrDefault，同一节点取多个值时用
  • 节点本次执行失败时取不到它的值（不会拿到上一次残留的结果），node.Status、node.Message 可查失败原因
  • 数值类型之间无损转换：int 结果可以按 double 读；2.5 不能按 int 读，超出范围也不行
  • 节点改名后脚本里的标题要跟着改

脚本类名由运行时生成，不要修改；构造函数可以注入应用中注册的服务，如 IProtocolManager。
