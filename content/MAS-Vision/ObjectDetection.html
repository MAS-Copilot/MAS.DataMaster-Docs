MAS.Vision - 深度学习（检测、分割、分类）

概述

VisionFlow「深度学习」分类下有三个节点，都加载 Ultralytics 导出的 ONNX 模型。类别、输入尺寸、任务类型从模型读出，换模型不用改流程；模型存进工程。

节点 用途 输出
目标检测 找目标、计数、定位 带类别的定位列表（框）
实例分割 量缺陷面积、长度 定位列表（按掩码测量）、合成掩码
图像分类 整张图或局部判 OK/NG 类别、置信度、合格判定
项目 支持情况
模型 YOLO26、YOLO11（YOLOv8 同格式）
任务 检测、旋转框（OBB）、分割、分类
输出格式 默认导出（需 NMS）、end2end=True 导出
推理 ONNX Runtime CPU；可选 CUDA
暂不支持 姿态
Note

Ultralytics 的代码与权重（包括用它训练出的模型）为 AGPL-3.0，闭源商用需由使用方购买其企业许可。

相关资料

训练与导出

环境

需要 Python 3.10 以上：

pip install ultralytics

没有 NVIDIA 显卡时先装 CPU 版 PyTorch：pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu。

数据集

检测、分割：

dataset/
├── images/train/  images/val/   # 图片
├── labels/train/  labels/val/   # 与图片同名的 .txt（检测为框，分割为多边形）
└── data.yaml

path: D:/dataset
train: images/train
val: images/val
names:
  0: 划痕
  1: 缺料

分类：按类别分文件夹，不需要标注文件：

dataset/
├── train/OK/*.jpg  train/NG/*.jpg
└── val/OK/*.jpg    val/NG/*.jpg
  • 样本覆盖不同光照、角度、背景
  • 类别名可以用中文，节点里按原名显示（标注图上显示为 #序号）

训练

任务 命令
检测 yolo detect train model=yolo26n.pt data=D:/dataset/data.yaml imgsz=640
旋转框 yolo obb train model=yolo26n-obb.pt data=... imgsz=1024
分割 yolo segment train model=yolo26n-seg.pt data=D:/dataset/data.yaml imgsz=640
分类 yolo classify train model=yolo26n-cls.pt data=D:/dataset imgsz=224
  • 小缺陷：调大 imgsz（如 1024），比换更大的模型更有效
  • 结果在 runs/<任务>/train/weights/best.pt

导出 ONNX

yolo export model=runs/detect/train/weights/best.pt format=onnx
  • 检测、分割默认导出为密集输出，节点里做 NMS（IoU 阈值有效）；加 end2end=True（仅 YOLO26）导出为端到端输出
  • 不要加 dynamic=True、half=True；nms=True 导出的模型暂不支持
  • 导入到不对应的节点（如分割模型导入目标检测）会提示该用哪个节点

目标检测、实例分割

  1. 节点库「深度学习」里拖出节点，输入接图像
  2. 设置窗口点「导入模型」选择 .onnx
  3. 运行一次，在左侧图上和下方结果表核对结果
  4. 误检多调高置信度阈值，漏检多调低；不需要的类别取消勾选
参数 说明
置信度阈值 默认 0.25
IoU 阈值 默认 0.7，仅密集输出有效
最多数量 默认 100
推理设备 CPU / CUDA（需先安装 GPU 运行时，见「GPU 推理」），CUDA 不可用时自动用 CPU
类别 取消勾选的不输出
端口 目标检测 实例分割
0 图像 原图直通 原图直通
1 定位 置信度最高的目标 同左
2 定位列表 全部目标（框中心、框宽高） 全部目标（掩码质心、掩码面积、最小外接矩形）
3 掩码 — 全部目标合成的掩码（0/255）
最后 标注图 框与标签 半透明掩码与轮廓
  • 结果数据：Count、每类的 Count.<类别名>，分割另有 TotalArea、Area.<类别名>
  • 没有目标不算失败（缺陷检测里没有缺陷是正常结果），单个定位输出没有值

常见搭配：

  • 按类别判定：检测/分割 → 列表筛选（属性「类别序号」）→ 计数判定
  • 缺陷尺寸：实例分割 → 列表筛选（面积或宽度）→ 像素转机械坐标（换算成 mm）
  • 合成掩码里重叠的目标会连成一片，接 Blob 分析得到的是连通块而不是实例（Blob 默认还会排除贴边区域）；量每个目标用定位列表
  • 只看局部：ROI 选择 → 检测/分割，提高小目标的相对尺寸

图像分类

  1. 拖出「图像分类」，输入接图像（只看局部时前面接 ROI 选择）
  2. 导入分类模型，运行一次看前几名
  3. 勾选算合格的类别，设置最低置信度
参数 说明
合格类别 第一名属于勾选的类别才合格；都不勾选时只输出结果不判定
最低置信度 默认 0.5，第一名低于它视为拿不准，判不合格
不合格时中止流程 默认只报警告并继续
  • 输出：0 原图直通，1 第一名置信度，最后为标注图（类别、置信度、OK/NG）
  • 结果数据：Label、Score、IsOk、Top（前 5 名）、每类的 Score.<类别名>

GPU 推理

程序随附 CPU 版 ONNX Runtime（640 输入的 n 检测模型约 15 ms/帧）。同时跑多个模型节点、模型较大或要求节拍时，用 NVIDIA 显卡推理：

要求 说明
显卡 NVIDIA 显卡，驱动支持 CUDA 13.0 及以上
空间 下载约 1 GB，安装后约 1.6 GB

一键安装

  1. 设置 → 依赖的组件 → ONNX Runtime GPU (CUDA) → 安装；程序自动下载、校验并解压到 runtimes\onnxruntime-gpu\win-x64
  2. 重启程序（ONNX Runtime 只在启动时加载，装好后要重启才生效）
  3. 节点的推理设备选 CUDA；运行后节点摘要显示 CUDA 即在用显卡

没有 NVIDIA 驱动或驱动太旧时安装按钮不可用，描述里会说明原因。升级程序后若 ONNX Runtime 版本变了，会提示版本不匹配，点安装即可更新。

离线安装（工控机不联网时）

  1. 在能联网的电脑上取得与程序 ONNX Runtime 版本对应的 GPU 运行时包 MasOnnxRuntimeGpu-win-x64-<版本>.7z（与一键安装是同一个包）
  2. 关闭程序，把包解压到程序目录（包里就是 runtimes\onnxruntime-gpu\win-x64）
  3. 启动程序，依赖组件页显示 CUDA 与 cuDNN 版本即成功

卸载：关闭程序后删除 runtimes\onnxruntime-gpu 文件夹。

首帧较慢：CUDA 第一次推理要初始化显卡与 cuDNN（约 1～2 秒），之后稳定。选了 CUDA 但不可用时自动改用 CPU

开发说明

位置 内容
MAS.Vision/Detecting 加载模型、预处理、解码、NMS、掩码重建、标注
MAS.VisionFlow/Nodes/DeepLearning 节点、共用基类与界面
MAS.VisionUnitTest/*ParityTests 与 Ultralytics 官方推理逐框、逐掩码、逐概率对比
MAS.VisionFlowUnitTest/*NodeTests 节点测试（自带小模型）
  • 处理流程与 Ultralytics 保持一致：letterbox 灰 114 补边；正框贪心 NMS、旋转框 probiou；掩码先放大到输入尺寸再缩放回原图；分类缩放与 PIL 逐像素一致。改动后跑对比测试确认仍一致
  • Agent 通过参数 ModelFile（模型完整路径，赋值即导入，空值清除；同一路径再赋值时文件内容变了才重新导入，并清空类别设置）导入模型，DisabledClasses、OkClasses 设类别（类别名或序号，逗号分隔）
  • 对比测试数据（官方模型、测试图、Python 结果）不进仓库，默认在 D:\MAS-YoloTest，可用环境变量 MAS_YOLO_TEST_DIR 指定；目录不存在时测试跳过
