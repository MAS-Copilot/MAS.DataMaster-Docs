清单格式与命令行

manifest.json

清单地址：{更新源根地址}/{通道}/manifest.json，通道固定为 stable 与 beta 两个。

客户端由设置页的「加入内测」开关决定读哪些通道：关闭时只读 stable； 开启时先读 stable 再读 beta，两份清单的 version 谁高就用谁，相同则 stable 胜出 （SemVer 规定同号正式版本高于预发布版本，因此内测用户在正式版发布后会自动切回正式包）。 beta/manifest.json 取不到时静默沿用 stable 的结果，内测通道未发过版本不影响正常检查。

{
  "schemaVersion": 1,
  "product": "MAS.DataMaster",
  "version": "3.22.0",
  "releaseDate": "2026-08-01",
  "minimumVersion": "3.21.0",
  "mandatory": false,
  "notes": "修复 DXF 多配方切换的轨迹越界问题",
  "notesUrl": "https://github.com/MAS-Copilot/MAS.DataMaster/releases/tag/v3.22.0",
  "packages": [
    {
      "rid": "win-x64",
      "selfContained": false,
      "url": "MasDataMaster-win-x64-v3.22.0.7z",
      "size": 139985920,
      "sha256": "3f786850e387550fdab836ed7e6dc881de23001b"
    }
  ]
}
字段 必填 说明
schemaVersion 否 清单格式版本，当前为 1
product 否 产品标识，避免误用其它产品的更新源
version 是 该通道的最新版本号，遵循 SemVer
releaseDate 否 发布日期，仅用于展示
minimumVersion 否 允许在线更新的最低当前版本，低于该版本的现场只能人工部署
mandatory 否 预留的强制更新标记
notes 否 更新说明，显示在设置页
notesUrl 否 更新说明网页地址
packages 是 各部署形态对应的更新包

包字段：

字段 必填 说明
rid 是 运行时标识，win-x64 或 win-x86
selfContained 否 是否自包含部署包，默认 false
url 是 包地址，相对清单所在目录的相对路径或绝对地址
size 否 字节数，仅用于展示
sha256 否 小写十六进制校验值。强烈建议填写，留空会跳过完整性校验

版本比较规则

遵循 SemVer 2.0：

  • 主次修订号按数值比较，3.22.0 > 3.21.9；
  • 预发布版本低于同号正式版本，3.22.0-beta < 3.22.0；
  • 预发布标识按点分段比较，数值段按数值比较：3.22.0-beta.2 < 3.22.0-beta.10；
  • 构建元数据（+ 之后）不参与比较；
  • 允许 v 前缀，允许省略修订号（3.22 等价于 3.22.0）。

只有清单版本严格高于当前版本时才提示更新。

包的匹配规则

客户端按当前部署的运行时标识（win-x64 / win-x86）与部署形态（框架依赖 / 自包含）匹配：

  1. 先找 rid 与 selfContained 都相同的包；
  2. 找不到则退而取 rid 相同的任意一个；
  3. 仍找不到则提示"更新源没有提供匹配当前部署的更新包"，不下载。

部署形态由应用目录下是否存在 hostpolicy.dll 判定。

更新包内容

包内既可以是固定文件夹包住的发布产物（MAS.DataMaster-win-x64/…，与人工分发时的结构一致）， 也可以是直接把发布产物放在根目录。压缩包名带版本号，包内文件夹不带版本号， 现场安装目录因此可以在首次部署时固定下来，后续更新只覆盖目录内的文件。 更新器会自动向下钻取：只含单个目录且没有文件时视为外层包装，最多钻 3 层。

包内必须含有主程序可执行文件、且文件总数不少于 8 个，否则判定为内容异常并终止更新。

格式支持 7z（LZMA2，CI 默认）与 zip，按文件内容自动识别，与扩展名无关。

更新器命令行

正常情况下由主程序自动唤起，参数无需人工拼装。人工排障时可以直接运行：

MAS.Updater.exe `
    --package "D:\pkg\MasDataMaster-win-x64-v3.22.0.7z" `
    --target  "D:\MasDataMaster" `
    --relaunch "MAS.DataMaster.exe" `
    --sha256 "3f786850e387550fdab836ed7e6dc881de23001b" `
    --version "3.22.0" `
    --relaunch-mode never `
    --log "D:\updater-log" `
    --result "D:\updater-log\result.txt"
参数 必填 说明
--package <path> 是 更新包（7z 或 zip）完整路径
--target <dir> 是 待覆盖的主程序安装目录
--relaunch <file> 是 更新完成后启动的可执行文件名，同时用作包内容的校验依据
--parent-pid <id> 否 主程序进程标识，更新器先等它退出，最长 60 秒
--sha256 <hex> 否 更新包校验值，省略则跳过校验
--version <ver> 否 目标版本号，用于日志与结果回执
--relaunch-mode <mode> 否 auto（默认，直接启动）/ ask（弹窗询问）/ never（不启动）
--no-relaunch 否 等价于 --relaunch-mode never
--keep-package 否 更新后保留更新包，默认删除
--log <dir> 否 日志目录，默认 %TEMP%\Updater\<目标目录名>
--result <path> 否 结果回执文件路径

直接运行时务必确认主程序已退出，否则更新器会等待超时并取消更新。

结果回执

更新器在退出前把结果写入 --result 指定的文件（主程序传入的是 %ProgramData%\MAS.DataMaster\Update\last-install.txt），主程序下次启动时读取并提示：

status=Success
version=3.22.0
timestamp=2026-08-01T09:15:32
backup=
message=已更新到 3.22.0
status 含义
Success 更新成功
RolledBack 更新失败，已回滚到更新前的版本，现场可正常运行
RollbackFailed 更新失败且回滚未完成，需人工处理，backup 字段指向保留的备份目录
InvalidArguments 启动参数不合法，未做任何改动

工作目录

主程序侧的更新文件都在应用目录之外，不受目录覆盖影响：

%ProgramData%\MAS.DataMaster\Update\
├─ Packages\                 已下载的更新包
├─ Runner\<时间戳>\           更新器副本（更新器无法删除运行中的自身，由主程序下次启动时清理）
├─ pending.json              待安装状态
└─ last-install.txt          上一次更新的结果回执

应用目录内只在更新期间存在 .mas-update-<时间戳>\（暂存与备份），成功或回滚后都会被清理， 只有回滚未完成时才会保留。

排错

现象 排查方向
提示"尚未配置更新源" 设置页的更新源为空
提示"更新源没有提供匹配当前部署的更新包" 清单的 rid / selfContained 与现场部署不符
提示"在线更新要求当前版本不低于 X" 版本闸门拦截，需人工部署
检查更新报网络错误 curl -I <清单地址> 确认可达；检查证书、防火墙与代理
下载后提示校验失败 清单里的 sha256 与包体不一致，多为重新打包后忘记更新清单，或包体上传不完整
发布后现场仍提示已是最新 清单被缓存：检查 Cache-Control，CDN 需刷新 manifest.json
更新后回滚，日志显示文件被占用 有进程仍占用应用目录（杀毒软件、残留子进程），把应用目录加入白名单后重试
更新后回滚，日志显示拒绝访问 应用目录不可写，换安装位置或以管理员运行
status=RollbackFailed 从回执的 backup 目录人工把内容搬回应用目录，并保留日志排查
