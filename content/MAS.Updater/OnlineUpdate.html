在线更新

MAS.DataMaster 支持从自建服务器或对象存储（OSS/COS）在线更新。检查与下载由主程序完成， 覆盖主程序目录由独立进程 MAS.Updater 完成，整个过程带完整性校验与失败回滚。

更新粒度是整个发布包，不做单文件增量。原因是单独替换某个 DLL 时，只要程序集版本或依赖关系 发生变化就会牵出一连串加载错误；整包覆盖的结果与人工解压新版本到现场目录完全一致， 是最稳妥也最容易验证的方式。

为什么需要独立进程

覆盖目录时不能有任何文件被占用，而运行中的可执行文件会锁住自身。因此更新器：

  • 以自包含单文件（约 11 MB）随发布包放在 Updater/MAS.Updater.exe；
  • 由主程序在启动前复制到应用目录之外（%ProgramData%\MAS.DataMaster\Update\Runner\<时间戳>\）再执行；
  • 不引用任何工程，第三方包只有解压用的 SharpCompress —— 复制出去后没有任何运行时依赖， 主程序无论是框架依赖还是自包含部署都能正常唤起它。

更新流程

主程序 MAS.DataMaster                      更新器 MAS.Updater（独立进程）
  │ 设置页「检查更新」→ 读取 manifest.json
  │ 比对版本 / 校验最低版本闸门
  │ 下载更新包 → 校验 SHA256
  │ 写入待安装状态 pending.json
  │ …现场继续运行，不打断业务…
  │ 用户正常退出应用
  ├─ 保存配置、释放资源
  ├─ 复制更新器到工作目录并启动 ─────────▶ 等待主程序进程完全退出
  └─ 进程退出                              再次校验更新包 SHA256
                                           解压到 <应用目录>\.mas-update-<时间戳>\new
                                           校验包内含主程序可执行文件
                                           逐个文件覆盖：旧文件移入 backup，新文件移入应用目录
                                           包外的文件原样不动
                                           校验主程序存在 → 清理暂存
                                           写结果回执 → 启动主程序 → 自身退出
                                           任一步失败 → 回滚到 backup 的旧版本

下载完成不会立即安装，只登记"待安装"。安装发生在应用正常退出之后，产线运行期间不会被打断。 应用被强制结束时待安装状态也不会丢失，下一次正常退出仍会完成安装。

覆盖与回滚

覆盖按"文件重命名"实现，而不是流式复制，且只处理发布包里有的文件：

  1. 该文件在应用目录已存在 → 旧文件移入 .mas-update-<时间戳>\backup\ 的同名相对路径；
  2. 解压出的新文件移入应用目录；
  3. 全部文件处理完后，校验主程序可执行文件存在。

同卷移动是文件系统的原子重命名，与文件体积无关 —— 实测 285 MB / 791 个文件耗时约 3 秒。 备份目录记录了本次动过的每一项，任一步失败都会把旧文件原样搬回，不会留下新旧混合的目录。

暂存目录放在应用目录内部，一是保证与应用目录同卷（跨卷移动会退化成复制，失去原子性）， 二是不需要对应用目录的父级有写权限。

结果 退出码 现场状态
成功 0 新版本已就位，暂存目录已清理
失败已回滚 1 旧版本原样运行，暂存目录已清理，日志留有原因
参数不合法 2 未做任何改动
回滚未完成 3 需人工处理，备份目录保留在回执的 backup 字段

现场数据保留

更新只覆盖发布包里有的文件，包外的一切原样保留，不需要维护任何保留清单：现场的 appsettings.json、人工放置的 runtimes\python、运行产物等都不会被动到。 工程、日志、数据库等现场数据默认位于 %ProgramData%\MAS.DataMaster，不在应用目录内，同样不受更新影响。

代价是旧版本里被新版本删掉的文件会残留在应用目录中：不影响运行，只占空间；需要彻底清干净时人工重新部署。

版本闸门

清单里的 minimumVersion 是允许在线更新的最低当前版本。填 3.20.0 表示只有 3.20.0 及以上的 现场可以在线更新到该版本，更早的现场会显示"在线更新要求当前版本不低于 3.20.0，请人工部署"， 不提供下载入口。

用途是拦截跨破坏性变更的升级：当某个版本改了工程文件格式、数据库结构或配置结构时， 把 minimumVersion 抬到该版本，老现场就只能走人工部署流程，避免自动更新造成停机。

该值维护在仓库的 scripts/Update/update-policy.json，发布流程会写进清单。

界面用法

设置页 →「在线更新」：

项 说明
检查更新 手动向更新源查询；卡片标题显示当前版本与部署形态（如 win-x64 / framework-dependent）
下载更新 下载并校验，完成后提示"更新已就绪，将在应用程序退出后自动安装"
立即安装并重启 走完整关闭流程（未保存的工程会拦截），随后由更新器覆盖并重启
放弃更新 删除已下载的更新包，取消待安装状态
更新源 更新服务器或对象存储的根地址
加入内测 开启后同时看 stable 与 beta 两个通道，版本高的一方胜出；关闭则只看 stable。默认开启
自动检查更新 打开设置页时自动查询
更新后询问再启动 开启后更新器会弹窗询问是否启动主程序

日志

位置 内容
%ProgramData%\MAS.DataMaster\Log\Updater\Updater.log 更新器的每一步操作、重试与失败堆栈
%ProgramData%\MAS.DataMaster\Log\Network.log 主程序侧的清单读取与下载
%ProgramData%\MAS.DataMaster\Log\System.log 待安装状态、更新器启动与结果回执

更新完成后主程序启动时会弹出提示，显示上一次更新是成功还是已回滚。
