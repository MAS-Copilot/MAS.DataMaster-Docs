MAS.DynamicViews.Variable

变量系统是 MAS.DynamicViews 的数据核心

整个动态视图运行过程中：

  • 控件绑定
  • 通讯同步
  • 运行时刷新
  • 状态显示
  • 事件交互

最终都依赖变量系统完成数据驱动

变量系统目标

变量系统主要目标：

  • 统一管理变量定义
  • 支持结构体变量
  • 支持字段级绑定
  • 支持变量监控
  • 支持批量更新
  • 支持通讯映射
  • 支持运行时绑定
  • 支持引用追踪
  • 支持高频实时刷新

变量模型

当前变量系统采用结构体变量 + 字段模型架构

整体结构：

DynamicViewVariableModel
├── VariableId
├── Name
├── GroupName
├── AccessMode
├── IsEnabled
├── Description
├── Usage

其中：

属性 说明
VariableId 结构体变量唯一标识
Name 结构体名称
GroupName 结构体分组
AccessMode 结构体访问模式
IsEnabled 是否启用
Description 结构体描述

普通结构体

普通结构体用于描述设备状态、工艺参数、按钮命令等常规数据

新增普通结构体时，系统会自动创建一个默认布尔字段，便于快速配置和测试。实施时建议按设备或工艺对象组织字段，例如

Conveyor01
├── Running
├── Fault
├── SpeedSet
└── CurrentSpeed

配方结构体

配方结构体用于通过 Modbus 保持寄存器与配方任务交互，它只承载信令，不包含数据区，固定占用 22 个保持寄存器

配方结构体的信令字段由通讯协议固定，不允许新增、删除、编辑或调整顺序；配方数据通过引用普通结构体进行配置

偏移 字段 说明
0–9 RecipeId 配方编号，定长 20 字节 ASCII 字符串
10 Operation 0 无操作，1 保存配方，2 装载配方，3 删除配方
11 Result 0 未执行，1 成功，2 失败
12–13 ElapsedMsLow / ElapsedMsHigh 操作耗时 INT32 的低位与高位
14 ErrorCode 错误码
15 AppliedRefCount 实际应用的引用结构体数量
16 FailedRefIndex 失败的引用序号，从 1 开始，0 表示无失败项
17 MissingRefCount 配方中不存在、未装载的引用结构体数量
18–21 Reserved01–Reserved04 预留字段

操作执行完由上位机把 Operation 清零并回写结果。回写因通讯中断失败时，下一轮读到同一操作码加同一配方编号只补回写、不重复执行操作，避免删除这类非幂等操作重跑后把首次的成功报成「配方不存在」

配方数据本体由配方结构体所引用的普通结构体承载：保存配方时采集这些结构体的当前值写入配方文件，装载配方时把文件里的快照写回这些结构体

配方随工程走，不再进数据库，落在工程文件所在目录下：

工程目录/
└── Recipes/
    └── 配方结构体名称/
        ├── structure.meta   配方目录的归属标记，记录配方结构体标识
        ├── P001.json
        └── P002.json
  • 配方结构体改名时目录一并改名，靠 structure.meta 认领旧目录，配方不会丢
  • 整个工程目录复制到另一台设备即可带走全部配方，无需导出导入
  • 配方编号即文件名，限 20 位字母、数字、下划线、短横线和点

引用配置在数据中心的字段列表下方维护，规则如下：

  • 只能引用启用状态、访问模式为读写的普通结构体，同一结构体不能重复引用
  • 引用不占用任何下位机地址，新增、删除、排序都不会影响地址表
  • 用新的配方编号保存即等价于复制配方，无需单独的复制操作码
  • 被配方引用的结构体不能删除，需先移除引用

配方记录以「配方结构体 + 配方编号」为唯一键，同一编号只有一个文件，不存在配方版本。修改引用配置后按下列规则投影：

  • 保存：以当前引用配置全量覆盖快照，配置中已删除的引用块被丢弃
  • 装载：结构体先按标识匹配、失配回退名称；字段先按标识匹配、失配回退名称；配方中不存在或类型不兼容的引用和字段不写入，保持当前值不变；快照中多余的引用与字段被忽略

配方的日常操作在动态视图工作台「更多 → 配方管理」中完成：

操作 说明
存为新配方 采集引用结构体当前值，保存为新的配方编号，等价于复制当前工艺参数；编号已存在时会先确认再覆盖
覆盖保存 用引用结构体当前值覆盖选中配方
装载配方 把选中配方的值写回引用结构体，设备参数立即改变
复制配方 复制选中配方已保存的快照到新编号，不受当前值影响
重命名 只改显示名称与备注，配方数据不变
删除配方 按配方编号删除，不可恢复

装载是逐个引用写下去的，中途失败即停止且不回滚：失败前已写入的引用保持新值，提示里会给出已写入的引用数，需要人工确认设备状态

右侧「配方内容」按引用结构体分页查看：标题栏右侧的下拉框选择要查看的结构体，表格列出该结构体在配方中保存的字段。每行的「操作」列提供两个动作，与变量监控一致：

  • 更改当前值：弹出输入框，确认后立即写入配方文件；值按字段类型校验，不合法则拒绝写入并保留原值
  • 恢复默认值：按工程中该字段的默认值还原，同样立即写入配方文件

在当前工程中已不存在的字段以删除线标出且不可操作，这些字段在装载配方时会被忽略。结构体被删除后又建了同名的，配方会按名称认回它，字段照常可编辑。修改配方值只改配方文件，不影响引用结构体的运行值，需要装载该配方后设备参数才会改变

报警结构体

报警结构体用于组织 Bool 报警点。创建时可指定 1 到 1000 个报警点，默认生成 100 个 Alarm001 到 Alarm100 字段。结构体默认为只读，每个字段使用描述作为报警信息，并保存“提示、警告、错误”三级报警等级

报警结构体按整体关联通讯通道和报警列表控件，不用于普通控件的字段级数据绑定。完整配置、运行和历史记录规则参见报警系统

系统结构体

系统结构体用于将上位机自身状态单向下发给下位机，例如当前画面、本地时间、运行状态与错误码。它有三条与其它结构体不同的规则：

  • 全工程唯一：每个工程只能创建一个
  • 单向下发：控件与脚本只读，通讯链路只写不读，下位机写入的值不会被采纳
  • 布局固定：固定占用 64 个保持寄存器，字段不允许新增、删除、改名或改类型

字段按功能分区排列，末尾预留 13 个寄存器用于后续扩展，不会影响既有字段的下位机地址：

分区 字段 说明
心跳与运行状态 Heartbeat 每次下发自增并自然回绕，下位机据此判断上位机是否存活
SystemState 0=初始化 1=就绪 2=运行 3=暂停 4=停止 5=故障
RunMode 0=离线仿真 1=在线
CommState 0=未启动 1=全部在线 2=部分离线 3=全部离线
DeviceOnlineCount / DeviceTotalCount 在线设备数与设备总数
UptimeSeconds 上位机已运行秒数
本地时间 Year / Month / Day / Hour / Minute / Second 分字下发，下位机可直接使用
Weekday 1=周一 … 7=周日
UnixTimestamp UTC 秒级时间戳
当前画面 CurrentScreenCode 当前画面号，定长 8 字节 ASCII
CurrentScreenType 0=无 1=页面；运行期可同时打开多个窗口，画面号只跟随页面
PreviousScreenCode 上一画面号，定长 8 字节 ASCII
ScreenChangeCounter 每次切换自增，便于下位机检测画面切换事件
错误与报警汇总 ErrorCode / ErrorLevel 错误码与等级，0 表示无错误
ActiveAlarmCount / HighestAlarmLevel / HasActiveAlarm 活跃报警数量、最高等级与报警状态
业务上下文 CurrentRecipeCode 当前配方编号，定长 20 字节 ASCII
RecipeState 0=未装载 1=已装载 2=装载中 3=装载失败
UserLevel 当前登录用户权限等级，取 UserRoles 枚举数值：0=无 1=游客 2=操作员 3=工程师 4=管理员 5=开发者
LanguageId 当前语种在工程语种清单中的位置，从 0 开始；不在清单内时为 255
预留 Reserved01 ~ Reserved18 预留字段

布尔量统一使用 UInt16 的 0/1 表示，避免与寄存器区混排；字符串字段使用定长 ASCII

下发节拍

系统结构体不使用独立计时器。绑定通道每次轮询到期时，会先刷新心跳、本地时间、运行时长与设备计数等字段，再将整个结构体写入下位机。

因此心跳节拍与通道轮询周期一致，通常设置为 500 毫秒即可。同一个系统结构体可以绑定多个设备通道，各通道按自身轮询周期独立下发。

通讯运行时启动时会先重置运行值并生成初始状态，因此即使未绑定通道，界面绑定的系统变量也不会为空。

停止运行时，会在轮询停止后、连接关闭前执行一次最终下发，使下位机收到 SystemState=4（停止），避免状态停留在运行态。

更新方式

字段分为两类维护：

  • 自动维护：心跳、本地时间、运行时长、设备计数、通讯状态、系统运行状态、当前画面、报警汇总、当前配方、登录权限等级、界面语言序号，由运行时各模块上报或在下发前拉取
  • 业务上报：错误码与错误等级，由业务代码调用系统变量服务写入

脚本可以通过脚本服务集合中的 SystemVariables 更新系统变量。自动维护字段即使被脚本写入，也会在下一次下发前被系统刷新覆盖

为什么使用结构体变量

传统动态组态通常采用全局变量列表模式

例如：

Motor1Running
Motor1Speed
Motor1Alarm

这种方式存在问题：

  • 变量数量巨大
  • 难以组织
  • 难以维护
  • 不符合 PLC 数据结构
  • 通讯映射复杂
  • 引用关系混乱

因此当前系统采用结构体变量组织数据

例如：

Motor1
├── Running
├── Speed
├── Alarm
└── Temperature

这样更符合

  • PLC 数据块
  • 设备结构
  • 工业对象模型
  • 通讯映射方式

字段模型

字段模型用于描述结构体中的具体数据点

典型结构：

DynamicViewVariableFieldModel
├── FieldId
├── Name
├── VariableType
├── DefaultValue
├── FixedString
├── Description
├── AlarmLevel
└── Properties

其中：

属性 说明
FieldId 字段唯一标识
Name 字段名称
VariableType 字段数据类型
DefaultValue 字段默认值，运行时按 VariableType 转换
Description 字段描述
AlarmLevel 报警等级，仅报警结构体使用，默认为 Warning
FixedString 固定字符串配置，仅字符串类型使用
Properties 扩展属性

字段类型切换时，系统会按类型重置默认值：

类型 默认值
Bool false
Int16 / UInt16 / Int32 / UInt32 0
Float / Double 0.0
String N/A

字符串字段需要配置固定长度字符串参数。固定长度默认 50 字节，默认编码为 ASCII，默认填充字符为 \0，并会去除末尾填充

字段占用

字段列表的「偏移」列显示该字段在结构体中的占用位置，按统一的结构体布局规则计算：

  • Bool 字段显示为「字节.位」，例如 4.1 表示第 4 字节的 bit1
  • 其它字段显示占用的字节范围，例如 2 ~ 3

连续声明的 Bool 字段共用一个布尔段，每个 Bool 占 1 位；遇到非 Bool 字段结束当前段，之后再出现的 Bool 另起新段。布尔段按字对齐、按 16 位整块计算，不足 16 位仍按完整 2 字节计算

Bool   Ready      0.0     ← 第一个布尔段（整段 2 字节）
Int16  Speed      2 ~ 3
Bool   Running    4.0     ← 第二个布尔段
Bool   Fault      4.1

偏移只依赖字段的类型与声明顺序，与是否配置通讯无关；调整字段顺序、类型或增删字段都会让后续字段的偏移发生变化

访问模式

访问模式定义在结构体变量层。当前结构体变量整体共享访问模式，而不是每个字段单独配置访问模式

访问模式主要用于：

  • 变量选择过滤
  • 控件绑定限制
  • 通讯读写限制
  • 写回限制
  • 后续权限控制

常见模式：

  • ReadOnly：可被通讯轮询读取，可作为显示和状态绑定来源，不允许写回
  • WriteOnly：不参与通讯轮询读取，只允许绑定到可写通讯通道并写出
  • ReadWrite：既可读取也可写入，适合参数读写和双向交互

注意：访问模式配置在结构体层级，一个结构体下的字段共享同一访问模式

命名与校验

结构体名称和字段名称必须符合变量命名规则：

  • 不能为空
  • 必须以字母或下划线开头
  • 后续字符可以包含字母、数字或下划线
  • 同一工程内结构体名称不能重复
  • 同一结构体内字段名称不能重复
  • 结构体至少需要一个字段

删除结构体或字段前，系统会检查引用。如果仍被控件绑定、控件事件（含事件里的每一条变量操作）、通讯通道或配方引用使用，需要先解除引用

停用的绑定同样算引用：停用只是暂时不生效，配置还留在工程里、随时可以再启用，放行删除就会留下悬空引用。拦截提示里这类引用会标注「已停用」，便于定位。要真正解除，得把那条绑定或动作删掉，或把它的变量、目标清空（切换页面与打开窗口的目标下拉框里选「无」）

批量更新

变量系统需要支持批量更新

原因是 PLC 通讯通常不是逐字段读取，而是按设备、通道或结构体批量读取

批量更新可以减少：

  • 通知次数
  • UI 刷新次数
  • Dispatcher 压力
  • 高频轮询开销

推荐运行时更新链路：

CommunicationService
    ↓
VariableService
    ↓
RuntimeBindingManager
    ↓
WPF Control

变量监控

变量监控用于观察运行时变量状态

通常显示：

  • 结构体名称
  • 字段名称
  • 数据类型
  • 当前值
  • 默认值
  • 访问模式
  • 启用状态
  • 更新时间

变量监控应读取运行时变量服务中的当前值，而不是直接依赖字段定义模型

运行时变量值规则：

  • 如果字段尚未收到通讯值或本地写入值，读取结果为字段默认值
  • 通讯轮询更新结构体时，会批量提交发生变化的字段
  • 只有值发生变化时才触发绑定刷新
  • 文本框和选中状态控件写入失败时，会恢复为变量中心中的当前值

变量操作

控件事件中的变量操作支持：

操作 Bool 数值类型 String
设置为 0 或 False false 0 空字符串
设置为 1 或 True true 1 "1"
取反 true/false 取反 0 与 1 切换 保持当前值
递增 保持当前值 加 1 保持当前值
递减 保持当前值 减 1 保持当前值

Int16、UInt16、Int32、UInt32 的递增递减会限制在类型范围内，避免溢出

引用追踪

变量系统需要支持引用追踪，引用追踪用于分析：变量字段被哪里使用

常见引用来源：

  • 控件绑定
  • 通讯通道
  • 事件配置
  • 后续报警配置
  • 后续趋势配置

引用追踪主要用于：

  • 删除检查
  • 重命名影响分析
  • 工程维护
  • 调试排查
  • 无效引用检测

克隆规则

变量模型和字段模型支持克隆

当前克隆方式基于 JSON 序列化和反序列化

克隆主要用于：

  • 编辑副本
  • 弹窗编辑
  • 撤销重做
  • 临时修改
  • 深拷贝模型

注意：克隆结果会复制当前对象数据，但应避免把运行时缓存、服务实例或临时状态放入变量定义模型中
