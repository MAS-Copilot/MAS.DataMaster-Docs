MAS.DynamicViews.AgentTools

MAS.DynamicViews 向 Agent 提供统一的通用模型工具集，不按单项功能分别定义工具。

动态视图包含大量属性且模型更新频繁。若按功能定义类型化工具，每次属性变更均需同步修改工具、工具说明和 Skill 文档，容易产生信息不一致。通用模型工具通过反射生成属性架构，并通过精简的人工注册表维护资源种类、提交目标和业务约束。

本文说明动态视图发生变更时，Agent 层是否需要同步调整，以及需要调整的具体位置。

工具清单

工具 风险 职责
dynamicViews.model.describe Low 返回资源种类清单及各资源种类的属性架构
dynamicViews.model.get Low 按种类列出实例，或读取单个实例在架构路径上的取值
dynamicViews.model.apply Medium 原子提交一组 create / update / bind / unbind 操作
dynamicViews.model.delete High 删除单个资源，并在删除前执行独立审批和引用检查
dynamicViews.query Low 返回工程概览和运行时变量值快照，以补充模型工具未覆盖的查询能力
dynamicViews.view.refresh Low 用内存工程重新渲染动态视图页面当前显示的画面
dynamicViews.view.navigate Medium 切换动态视图页面显示的画面

模型属性使用扁平化点分路径，每条路径对应一次赋值，例如 layout.left、text.content、modbusTcpConfig.ip 和 binding.color.trueBackground。写入接口不接受嵌套 JSON，因此可以将校验错误定位到具体字段。

核心分界线

以下边界用于区分自动生成内容与需要人工维护的内容。实施变更前，应先确定变更所属类别

由反射自动生成：

  • 属性名、类型、允许值、默认值，来自模型反射
  • 自动排除带 [JsonIgnore] 的派生属性，例如控件上的 SupportsBackground 等能力标志
  • 控件有哪些属性分节，来自 DynamicViewControlDescriptorRegistry 的属性分组与能力位
  • 控件支持的绑定通道及各通道允许的变量类型，来自描述符与 DynamicViewBindingChannelRules
  • 控件预设目录，来自 DynamicViewPresetRegistry

需要人工同步维护：

位置 维护内容 变动频率
DynamicViewModelKindRegistry 资源种类、定位方式、支持的操作、提交目标、校验器和引用锁定路径 新增资源种类时
DynamicViewModelSchemaFactory.ValueKinds CLR 类型到 JSON 取值形态的映射表 引入新的标量类型时
DynamicViewContentFactory 页面、窗口、背景的新建口径（名称、画面号、尺寸、分组） 新建规则变化时
DynamicViewModelSchemaFactory.CompositeStructTypes 有标量替身的 WPF 复合结构体 极少
DynamicViewsToolProvider.ModelCreate 各资源的构造方式及所属位置 新增支持创建的资源时
DynamicViewsToolProvider.ModelDelete 删除前的引用与业务守卫 新增可删除的资源时
DynamicViewsToolProvider.Guards.EditorWindows 哪个编辑器窗口持有哪些区域的工程副本 新增编辑器窗口时

提交路径需要显式维护：结构体使用 SetStructures，设备使用 SetCommunicationDevices，设计器内容使用 SetDesignerProject，画刷还需要重新注入画刷库。此类对应关系无法通过模型反射可靠推导。

改动对照表

常见变更可分为以下类别，各类别对应不同的 Agent 层维护要求。

为控件新增属性

无需修改 Agent 工具。将属性添加到对应的分节模型（如 DynamicViewLayoutModel、DynamicViewTextModel）后，describe 与 apply 将自动识别该属性。

只在两种情况下需要额外动作：

  • 不应向 Agent 公开的属性，应添加 [property: DynamicViewAgentHidden]
  • 仅允许在创建时设置的属性，应添加 [property: DynamicViewAgentReadOnly("原因", isSettableAtCreation: true)]

若属性类型未在 ValueKinds 表中注册，架构会将其标记为 Unsupported 并设置为只读，同时 NoPropertyFallsBackToUnsupported 测试会失败。此时应补充类型映射，不应修改该测试断言。

新增一个控件类型

无需修改 Agent 工具。在 DynamicViewControlDescriptorRegistry 中注册描述符，并声明属性分组、绑定通道、外观能力和附加能力。

若该类型需要支持工具创建，还应在 DynamicViewPresetRegistry 中注册预设。未注册预设的控件类型不能通过工具创建；图形类控件属于此类，仅支持在设计器中绘制。

新增一个属性分组

在 DynamicViewPropertyGroups 中新增枚举值，并在 DynamicViewControlPropertiesModel 中新增同名的可空子模型。两处名称必须保持一致；名称不一致时，相应分节不会进入生成结果，EveryControlTypeProducesSchemaWithResolvableSections 测试用于检测此类问题。

新增一个绑定通道

在 DynamicViewBindingChannels 中新增枚举值，在 DynamicViewControlBindingsModel 中新增同名属性，并在 DynamicViewBindingChannelRules 中声明允许的变量类型。通道配置将自动显示在 binding.<通道>.* 路径下。

新增资源种类（例如画布、图层或模板）

该场景需要按以下顺序完成配套变更：

  1. DynamicViewModelKind 加一个枚举值
  2. DynamicViewModelKindRegistry 登记描述符：模型类型、标识与名称属性、父级种类、支持的操作、提交去向、必要的校验器与引用锁定路径
  3. ModelShared.TryGetEntries 加一条定位分支
  4. 如果支持新建，ModelCreate.TryBuildInstance 加一条构造分支
  5. 如果支持删除，ModelDelete 加守卫与移除分支
  6. 如果它由某个新窗口编辑，Guards.EditorWindows 加一行
  7. 如果它落在新的持久化区域，DynamicViewProjectRegion 与 DynamicViewModelCommitTarget 各加一位，并在 ApplyRegions 里补赋值

EveryKindDeclaresCommitTarget 用于验证第 2 步是否已声明提交目标。若遗漏第 3 至第 5 步，运行时将报告“尚未接入模型工具”或“声明了可删除但没有移除实现”。

新增一个编辑器窗口

在 Guards.EditorWindows 中新增配置，声明该窗口持有的工程区域。占用检查根据本次变更的提交区域执行，仅阻止存在冲突的窗口，不影响其他已打开窗口。

必须遵循的五项约束

以下约束用于补充反射无法识别的业务语义，避免产生部分更新或数据不一致。

成对维护的属性不得暴露为可写路径

对于通过 UpdateTarget / ClearTarget 等方法成对维护的属性，必须标记 [DynamicViewAgentReadOnly]，并将写入操作引导至专用操作。

当前包括两类属性：通讯通道的 StructureId / DisplayName，以及控件字段绑定的 VariableId / FieldId / DisplayName。分别写入这些属性可能导致标识与显示名称不一致，使界面显示的关联对象与实际轮询对象不一致。

守卫：PairedTargetPropertiesAreNotWritable

可写集合的元素投影必须无损

集合能整体替换写入的条件有四条，缺一不可：

  • 集合本身有公开 setter
  • 元素是本程序集的模型且有无参构造
  • 元素类型没有被任何种类接管（有种类的走那个种类，否则绕过它的校验与引用检查）
  • 元素的全部公开字段都是可写标量

第四项是保证无损写入的必要条件。整体替换数组时会根据元素字段重新构造每个元素；若元素还包含子集合或不可写字段，读取后再次写入将导致相关数据丢失。

多语言分类与词条同时命中第三、四两项：它们各自登记为资源种类，因此 catalogs 与 entries 保持只读，只读原因直接指向应当使用的种类。

当前全库可整体写入的集合只有两条：binding.state.states 与 binding.comboBox.items

守卫：WritableListItemsAreLosslesslyProjected、ReplaceableListsAreWritableAndChildListsAreNot、CatalogListStaysReadOnly

名称仅在父级内唯一，定位结果必须唯一

字段名在结构体内唯一、通道名在设备内唯一、控件名在页面内唯一，跨父级都可能重名；页面、窗口、背景之间也可以重名

因此，定位操作仅在唯一匹配时继续执行。出现多个匹配项时，应拒绝操作并提示提供 parentId 或唯一标识。所有定位路径均不得使用 FirstOrDefault 直接选取首个结果。

画刷 Key 属性必须显式标注

外观前景、背景、边框，图形填充与描边，图标前景，颜色绑定的四个色值，多状态的回退背景与各状态背景，存的都是画刷资源 Key，不是颜色值。这些属性在 CLR 层面就是 string，反射无法与普通文本区分，因此必须用 [property: DynamicViewBrushKey] 标注。

标注后架构会输出 isBrushKey，写入前按"工程画刷 + 主题画刷"校验 Key 是否存在。缺少标注时，模型会把 #FFE8E8E8 这类颜色值直接写进去：控件回退默认外观，属性面板显示红色删除线，且不会有任何报错。

新增画刷 Key 属性时，除标注特性外无需改动工具。主题资源字典不可用时（脱离 WPF 资源环境）校验自动跳过，不会把全部 Key 判为无效。

守卫：宿主层的 外观颜色值被拒绝并提示先建画刷、主题画刷与同批次新建画刷都可引用

跨区域改动一次事务提交

一组操作可能同时修改画刷与设计器内容。若逐项调用 Set*，中途发生异常时可能仅提交部分区域，不符合失败时不产生任何变更的原子性要求。

因此，跨区域提交统一使用 IDynamicViewProjectPersistenceService.ApplyRegions：一次完成所有区域赋值，并仅执行一次脏状态标记和变更通知。画刷重新注入属于界面刷新，不属于事务，应在提交完成后调度至 UI 线程执行。

守卫：宿主层的 跨区域批量改动一次提交

写入的执行链路

model.apply
  ├─ 门禁：工程是否打开、通讯是否停机
  ├─ 创建工程副本
  ├─ 在副本上依次执行操作
  │    ├─ 定位（唯一性检查）
  │    ├─ 引用锁定路径检查（禁止修改已引用结构体的访问模式和字段类型）
  │    ├─ 画刷 Key 存在性检查（工程画刷 + 主题画刷）
  │    ├─ 按架构路径写值（类型、允许值、可写性）
  │    └─ 种类校验器（重名、取值范围、访问模式兼容…）
  ├─ 任一操作失败 → 放弃整批操作，不修改内存工程
  ├─ 按本次提交区域检查编辑器窗口占用
  ├─ ApplyRegions 一次事务提交
  ├─ 画刷重注入（UI 线程，事务之外）
  └─ 当前画面重新渲染（UI 线程，事务之外）

执行过程遵循先在副本中完成操作，再统一提交的原则。该机制既保证原子性，也允许同一批次中的后续操作引用先前创建的对象。例如，创建结构体、设备和通道，并将通道绑定至结构体，可在一次调用中通过名称完成，无需预先获取实际标识。

画面刷新

模型工具只改内存工程，动态视图页面已经渲染出来的可视树不会自行更新。因此 model.apply 与 model.delete 在提交成功后会顺带刷新当前画面，与设计器关闭后调用 RefreshCurrentPage 的行为一致，结果中的 isViewRefreshed 说明本次是否刷新成功。

刷新依赖 IDynamicViewNavigationService.CurrentHost：内容宿主由动态视图页面创建，导航服务在每次导航时记录它，工具层据此在不引用界面的前提下刷新页面。宿主的生命周期与导航状态无关，Reset 不清空该引用。尚未打开工程时 CurrentHost 为空，此时写入照常提交，isViewRefreshed 返回 false。

工具在 IPC 线程执行，刷新与导航必须封送至 UI 线程，统一走 ...View 中的 InvokeOnUi。

架构指纹

DynamicViewModelSchemaFactory.SchemaVersion 根据全部资源种类和控件类型的属性路径、值类型及可写性计算，并使用 SHA-256 哈希值的前 12 位。模型属性发生增删改时，架构指纹将同步变化。

每个 describe 和 get 响应均包含该指纹，调用方可据此判断缓存架构是否失效。因此，模型变更后无需额外通知调用方，后续调用可自动检测架构变化。

两类不走属性路径的写入

以下两项无法表达为固定的扁平属性，各自由一种专门机制承载。它们是架构引擎的扩展点，新增同类资源时应沿用现有机制，不要另加工具。

合成标识：控件事件

控件的三个鼠标事件在模型上没有标识属性，实例由所在位置决定。描述符通过 SyntheticIds 声明全部合法标识（Click、MouseDown、MouseUp），定位层用 ModelEntry.Key 承载该标识，describe 把它作为 ids 返回给调用方。

事件下的变量操作是一个有序列表，元素为成对维护的字段绑定，不满足无损投影条件，因此标注为只读并引导至 bind / unbind：bind 追加一条（structure + field + operationType），unbind 按 index 移除或整体清空。切换页面与打开窗口则是普通属性路径 navigate.* 与 openWindow.*，按内容标识引用目标，由 DynamicViewControlEventValidator 校验引用存在性。

事件模型在控件上可空，首次配置时才创建。因此 TryGetEntries 区分读写意图：写入路径按需补齐事件模型，读取路径返回默认值而不写回工程。

动态键映射：多语言词条

词条正文的键是已配置的语言，随工程变化，无法由静态反射展开成固定路径。因此引入 DynamicViewModelValueKind.Map：Dictionary<string, string?> 属性整体作为一条路径公开，写入时按键合并——请求中出现的语言覆盖原值，未出现的语言保留原文，合并在原字典实例上进行以保留模型指定的键比较器。

分类与词条各自登记为资源种类（LanguageCatalog、LanguageEntry），提交去向为 Languages 区域，由 DynamicViewLanguageStore 整目录重写 resx。分类名同时是 resx 目录名、词条键名同时是引用键的后半段，两者的格式与重名规则由 DynamicViewLanguageValidator 校验；被控件文本引用的分类与词条禁止删除。

排查清单

写入被拒绝时，依次检查：

  • 通讯运行状态是否为 Stopped
  • 与变更区域对应的编辑器窗口是否已关闭（结构体对应数据中心、控件对应设计器、画刷对应画刷中心、语言对应语言中心）
  • 路径是否由 describe 返回，而非自行构造
  • 该路径是否被标为不可写，readOnlyReason 会说明原因与替代入口
  • 子资源是否给了 parentId

当架构与实际模型不一致时，应首先运行 MAS.DynamicViewsUnitTest 中的 DynamicViewModelSchemaFactoryTests。该测试集覆盖分节解析、类型映射、标识只读、成对属性、集合无损投影和能力覆盖，可用于识别大多数模型漂移问题。
