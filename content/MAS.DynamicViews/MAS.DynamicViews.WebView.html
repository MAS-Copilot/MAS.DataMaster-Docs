MAS.DynamicViews.WebView

Web 视图是 DynamicViews 的第二套前端方案，与 WPF 组态视图并行存在、同时运行、互不替代

组态视图 Web 视图
技术 WPF 控件 + 设计器 HTML / CSS / JavaScript
维护方式 设计器拖拽配置 Agent 直接编写代码，无可视化设计器
运行位置 DataMaster 内 DataMaster 内窗口、本机浏览器、局域网终端（平板、手机、其他电脑）
变量来源 变量中心 同一个变量中心
写入通道 IDynamicViewVariableWriteService 同一个写入服务
账号与角色 DataMaster 用户体系 同一个用户体系

两套前端不直接通信，而是共用变量中心：

PLC / 通讯轮询 ─┐
组态视图写入 ───┼─→ VariableWriteService ─→ 变量中心(ValueChanged) ─┬─→ 组态视图刷新
Web 视图写入 ───┘                                                  └─→ 变量网关 ─→ 所有 Web 客户端

因此任意一端写入后，其余各端都会收到更新；多个 Web 页面、多个客户端可以同时订阅不同变量。

Note

“跨平台”指同一局域网内任何带浏览器的设备都能访问 Web 视图；服务端仍是 Windows 上的 DataMaster 进程，Web 页面不能脱离 DataMaster 独立运行。

工程结构

Web 视图属于动态视图工程，位于工程目录下的 Web/。默认工程没有该目录，由 Agent 按需创建。

整个 Web/ 是一个前端工程：主题、脚本、布局全站共用，页面可以任意组织，也可以做成单页应用。

<工程目录>/Web/
├── manifest.json          应用清单（唯一）：标题、入口、权限、全局变量表、登记页面
├── index.html             入口页，站点根地址 http://主机:端口/ 打开它
├── pages/
│   └── motor.html         任意数量的页面，目录结构不限
├── assets/
│   ├── theme.css          全站主题，所有页面共用
│   ├── common.js          全站脚本：页头导航、登录/退出、连接状态
│   └── img/ …
├── _sdk/
│   └── dynamic-views.js   前端 SDK，DataMaster 在 Web 目录创建后放入
├── _shared/
│   ├── echarts.min.js …   共享第三方库（ECharts、Tailwind、daisyUI、Alpine、GSAP 等，见下）
│   └── icons/             Lucide 全量图标（2000 多个 .svg）
├── web.json               服务设置，由 DataMaster 维护
└── .covers/               页面封面截图，由 Agent 工具生成
  • 站点根目录就是 Web/，页面之间用根相对地址引用：/assets/theme.css、/pages/motor.html。
  • 以 . 开头的目录和文件（如 .covers）不对外提供。
  • 工程“另存为”时 Web/ 随工程一起复制。

应用清单

Web/manifest.json 是 Web 视图唯一的配置文件，支持注释与尾逗号，枚举使用 camelCase。

{
  "title": "产线监控",
  "description": "电机、温度与报警",
  "entry": "index.html",
  "auth": { "viewRole": "none", "writeRole": "operator" },
  "variables": {
    "motor.speed":   { "structureId": "3f2a…", "fieldId": "b91c…", "access": "read",      "type": "int32" },
    "motor.running": { "structureId": "3f2a…", "fieldId": "c7d0…", "access": "readWrite", "type": "bool" },
    "motor.target":  { "structureId": "3f2a…", "fieldId": "e41f…", "access": "readWrite", "type": "int32", "writeRole": "engineer" }
  },
  "pages": [
    { "path": "index.html",       "title": "总览",     "icon": "layout-dashboard" },
    { "path": "pages/motor.html", "title": "电机控制", "icon": "fan", "viewRole": "operator" }
  ]
}

顶层字段

字段 说明
title / description 应用标题与描述，显示在 DataMaster 面板与页面导航
entry 入口页相对路径，默认 index.html
auth 应用级权限，见权限与登录
variables 全局变量表：别名 → 变量声明，所有页面共用
queries 查询表：别名 → 数据源上的一条只读 SQL，见后端查询
pages 登记页面：出现在 DataMaster 页面卡片、SDK 的 dv.pages 中，并用于页面级登录提示；未登记的 HTML 同样可以访问

变量声明

结构体与字段标识是 GUID，页面代码不直接使用它们，而是使用清单中声明的别名。按标识绑定，结构体或字段改名不影响页面。

字段 说明
别名（键） 点分隔的若干段，每段以字母或下划线开头，只含字母、数字、下划线、连字符，总长不超过 64，区分大小写
structureId / fieldId 结构体与字段标识，必须来自工程，不可编造
access read / write / readWrite，只能在结构体自身访问模式之内收窄
type 可选，期望的字段类型；字段类型被改动后校验失败，而不是让页面静默出错
readRole / writeRole 可选，单个变量的读 / 写角色门槛，与应用级角色取较高者

登记页面

字段 说明
path 相对 Web 目录的 HTML 路径
title / description / icon / tags 展示信息，icon 为 Lucide 图标名
viewRole 打开页面所需角色，仅用于 SDK 的登录引导与导航显示

校验规则

DynamicViewWebProjectValidator 由界面、Agent 工具与变量网关共用：

  • 入口页与登记页面必须是 Web 目录内存在的 .html/.htm，不能越界、不能位于隐藏目录，登记不能重复
  • 角色取值只能是 none、visitor、operator、engineer、admin、developer
  • 变量：别名合法；结构体存在且启用；字段存在；声明的 type 与字段一致；只写结构体不能声明读取；只读结构体与系统结构体不能声明写入
  • 警告：writeRole 为 none 且存在可写变量；文件引用了外部主机资源（CDN）；声明了变量但没有页面引用 SDK

变量网关连接时逐个解析变量：未通过的变量不可订阅、不可写入，但不影响其余变量与页面运行。

后端查询

Web 视图支持通过查询声明读取数据库中的历史数据，例如趋势、报警历史和产量统计。

页面只需要调用已声明的查询并提供参数，SQL、数据库连接信息及访问权限均由服务端管理，页面和 Agent 无法直接访问。

数据源

数据源是工程中配置的数据库连接。在 Web 视图面板的「数据源」中进行配置，要求工程师及以上权限

每条查询可指定所使用的数据源。

配置项 说明
标识 字母开头，仅允许字母、数字和下划线，最多 32 个字符。保存后不可修改
名称 / 说明 用于显示和说明
类型、服务器、端口、数据库名、用户 数据库连接信息，目前支持 MySQL
密码 使用 DataMaster 应用加密服务加密保存，不以明文存储。编辑时留空表示保持原密码
查询超时 1～60 秒，默认 30 秒。超时后取消查询并返回 QUERY_TIMEOUT
  • 数据源保存在工程 .masproj 清单中，不属于页面文件，也不会作为工程模型的一部分进行序列化或克隆
  • Agent 只能查看数据源的标识、名称、数据库名及使用情况，无法查看服务器、账号和密码，也不能创建或修改数据源
  • 被查询声明引用的数据源无法删除

建议使用数据库只读账号。 SQL 只读校验用于防止误操作，数据库自身的权限控制仍应作为主要安全措施

查询声明

查询通过工程清单中的 queries 进行声明：

"queries": {
  "alarmHistory": {
    "source": "main",
    "sqlFile": "sql/alarm-history.sql",
    "description": "报警历史，按时间倒序",
    "readRole": "operator",
    "rowLimit": 2000,
    "parameters": {
      "from": { "type": "dateTime" },
      "to": { "type": "dateTime" },
      "level": { "type": "number", "default": 1 }
    }
  }
}
配置项 说明
查询别名 查询的唯一名称，规则与变量别名一致
source 数据源标识，必须已配置
sql / sqlFile 内联 SQL 或 SQL 文件，二选一。SQL 文件必须位于 Web 目录内且扩展名为 .sql，不会通过 HTTP 提供给浏览器
parameters 查询参数声明。页面只能传递已声明的参数
readRole 执行查询所需的最低角色，与 auth.viewRole 共同决定实际要求
rowLimit 返回行数上限，默认 5000，最大 50000。超过限制时返回 truncated: true
description 查询说明，会随 Web 视图信息提供给页面

查询参数

参数通过 parameters 声明：

"parameters": {
  "from": {
    "type": "dateTime",
    "required": true
  },
  "to": {
    "type": "dateTime",
    "required": true
  },
  "level": {
    "type": "number",
    "required": false,
    "default": 1
  }
}

支持以下类型：

类型 说明
text 文本，默认类型
number 数值
boolean 布尔值
date 日期，格式为 yyyy-MM-dd
dateTime ISO 8601 日期时间

参数类型由服务端根据声明进行转换和校验，页面不能自行指定参数类型。

required 默认为 true。配置 default 后，页面可以省略该参数或传入 null。

SQL 中使用 {{参数名}} 引用参数：

SELECT *
FROM alarm_history
WHERE alarm_time >= {{from}}
  AND alarm_time < {{to}}
  AND level >= {{level}}
ORDER BY alarm_time DESC;

参数会作为数据库参数绑定，不会直接拼接到 SQL 文本中。

不要在页面中拼接 SQL。查询逻辑应在 SQL 或 SQL 文件中定义，页面只负责调用查询并传递参数。

SQL 限制

查询只能执行单条只读 SQL 语句，支持：

  • SELECT
  • WITH
  • SHOW
  • DESCRIBE
  • EXPLAIN

以下类型的操作会被拒绝：

  • INSERT
  • UPDATE
  • DELETE
  • DROP
  • ALTER
  • CREATE
  • TRUNCATE
  • EXEC
  • 多条 SQL 语句

参数必须通过 {{参数名}} 使用。注释和字符串中的 {{参数名}} 不会被识别为查询参数。

查询权限

查询可以通过 readRole 限制最低访问角色：

{
  "readRole": "operator"
}

实际访问权限同时受 Web 视图的 auth.viewRole 和查询自身的 readRole 限制。

查询结果

查询返回列信息和数据行。

当返回数据超过 rowLimit 时，结果会包含：

{
  "truncated": true
}

单次查询结果还有约 8 MB 的消息大小限制。超过限制时返回 RESULT_TOO_LARGE。

并发限制

为避免查询占用过多数据库资源：

  • 单个 WebSocket 连接最多同时执行 4 个查询
  • 所有连接合计最多同时执行 6 个数据库查询
  • 超出限制时返回 BUSY
  • 查询不会阻塞变量写入和订阅数据推送

查询失败以及执行时间超过 3 秒的查询会记录到 DynamicView.log。

数据库错误信息中的数据库密码等敏感连接信息会自动隐藏。

查询验证

可以使用 dynamicViewWeb.validate 检查查询配置，也可以在 Web 视图面板中进行校验。

校验包括：

  • 查询别名是否合法
  • 数据源是否存在
  • sql 与 sqlFile 是否正确配置
  • SQL 文件是否存在且位于 Web 目录内
  • SQL 参数是否全部完成声明
  • 参数默认值是否符合声明的类型
  • readRole 是否有效
  • rowLimit 是否有效

声明了但未在 SQL 中使用的参数会产生警告。

只读 SQL 会在实际执行时再次进行安全校验，可使用 dynamicViewWeb.query 预览查询结果。

与图表资产的区别

Web 视图查询与图表资产查询均支持读取数据库，但使用方式不同：

项目 图表资产 Web 视图
数据库 工程共用数据库 支持多个命名数据源
查询方式 指定 SQL 文件 指定已声明的查询
参数 页面提供 必须预先声明
参数类型 由请求提供 由服务端声明并校验
权限 无查询级角色限制 支持查询级角色限制
SQL 安全 只读校验 只读校验
查询超时 无 支持配置
结果限制 无统一限制 支持行数及消息大小限制

服务宿主

IDynamicViewWebHostService 使用独立的本地 Web Host 实例（LocalWebHostFactory.Create），与图表资产共享的 Host 互不影响启停。

设置 说明
端口 固定端口，默认 18088，便于局域网终端收藏地址；被占用时启动失败并提示更换
访问模式 仅本机（127.0.0.1）或局域网（0.0.0.0），默认仅本机
随工程自动启动 打开工程后按设置自动启动服务
局域网 HTTPS 加密 httpsEnabled，默认关闭，仅局域网模式生效；见下文“局域网 HTTPS”
HTTPS 端口 httpsPort，默认 18443；只在 web.json 里修改，面板不提供入口
IP 白名单 ipAllowListEnabled 与 allowedAddresses，默认关闭；见下文“IP 白名单”

设置保存在 Web/web.json，属于工程。切换工程时服务先停止，再按新工程的设置决定是否自动启动。停止服务会断开全部客户端，并使全部独立登录失效。

局域网 HTTPS

在面板“设置”里勾选“局域网 HTTPS 加密”（停止服务时修改，启动后生效；需要管理员）：

  • 局域网终端改用 https://局域网地址:18443/ 访问，不再提供局域网明文 HTTP；面板里的局域网地址、二维码、复制链接为 https 地址
  • 本机（DataMaster 内的窗口、Agent 的 verify / cover）仍走 http://127.0.0.1:18088/，不受证书影响
  • 证书是自签名的（RSA 2048，有效期约 2 年），保存在 DataMaster 数据目录的 WebCertificates/web-lan.pfx（本机文件，不随工程复制），包含本机当前所有局域网 IPv4 与机器名
  • 当证书里没有的局域网地址、证书临近过期或文件损坏时，下次启动服务会自动重新生成
  • 局域网 IP 无法申请公共证书，所以终端首次访问会出现浏览器安全警告：在浏览器里选择“高级 → 继续访问”即可，同一地址后续不再提示（每台终端、每个浏览器各一次）。证书重新生成后需要再确认一次
  • 页面地址的证书被接受后，同一地址的 WebSocket（wss://）自动可用，SDK 按页面协议选择 ws/wss，页面无需改动
  • 自签名证书解决的是明文传输（同网段抓包窃取账号密码），不能防止中间人主动冒充；确认警告时请核对地址是本机的局域网地址

IP 白名单

面板“设置”里勾选“IP 白名单”并在下方文本框填写允许访问的地址（需要管理员），或直接编辑 web.json：

  • 每项可以是单个 IP（192.168.1.20）或网段（192.168.1.0/24），以逗号、分号、空格或换行分隔；写成 192.168.1.5/24 会规整为 192.168.1.0/24。面板保存前会校验，无法识别的条目会被提示并拒绝
  • 默认关闭。启用后，名单外的局域网来源在 TCP 连接建立后立即被中止（不进入 TLS 握手、不返回任何页面），日志里按地址每分钟最多记一条拒绝记录
  • 本机（回环地址）始终允许，DataMaster 内的窗口与 Agent 验证不受影响
  • 启用但名单为空（或全部无法解析）时，局域网来源一律被拒绝
  • 修改立即生效，无需重启服务：已经在线但不在新名单内的客户端会被立即断开（同“在线客户端”里的断开，客户端不再自动重连）
  • 白名单只按来源 IP 判断，不能防止 IP 被冒用或经过 NAT / 代理的场景（此时来源是代理的地址）；它是网络隔离之外的补充，不替代登录与变量权限

路由

所有请求由 DynamicViewWebEndpoint 处理：

路径 说明
/ 清单 entry 指定的入口页；没有 Web 工程时返回占位页
/{相对路径} Web 目录内的静态文件；目录取其 index.html
/_sdk/…、/_shared/… 工程里 Web/_sdk/（SDK）、Web/_shared/（共享库与图标）下的文件，和其他文件一样按静态文件提供（没有内置回退）
/_shared/icons/{name}.svg 工程里的 Lucide 图标
/ws/dynamic-views 变量网关 WebSocket
  • 只接受 GET / HEAD，其余方法返回 405；不提供任何 HTTP 数据接口。
  • 路径中含 ..、盘符、空字符或以 . 开头的段一律拒绝，解析结果必须位于 Web 目录内。
  • 逐段按磁盘上的真实名称核对：8.3 短名（如 COVERS~1）、末尾点等别名不会命中真实文件；真实名称以 . 开头的条目、符号链接 / 目录联接一律不提供。
  • 根目录的 manifest.json、web.json（及其临时文件）不对外提供，页面所需的清单信息由网关 welcome 下发。
  • 所有响应带 X-Content-Type-Options: nosniff。
  • 页面文件带 ETag（长度 + 修改时间）与 Last-Modified，SDK 带按内容哈希的 ETag；均为 no-cache，浏览器每次重新验证，未变化时返回 304。
  • WebSocket 握手校验 Origin：浏览器发起的连接必须与请求的 Host 同源，否则返回 403（防跨站 WebSocket 劫持）；不带 Origin 的非浏览器客户端放行。
  • 连接数上限：全局 256 条，同一远程地址 32 条（本机连接不受单地址限制），超出以 TOO_MANY_CONNECTIONS / 关闭码 4029 拒绝。

SDK、图标与共享库

Web 页面统一使用工程内的相对路径引用 SDK、图标和共享库：

<script src="/_sdk/dynamic-views.js"></script>
<i data-dv-icon="gauge"></i>
<script src="/_shared/echarts.min.js"></script>

Web 目录为站点根目录，因此上述资源均为工程文件，无需配置额外路由，也不提供内置回退

  • 默认资源：Web 目录创建或读取时，DataMaster 会自动提供 SDK、Lucide 图标和 ECharts 资源：

    • /_sdk/dynamic-views.js

    • /_shared/icons/ 下的 Lucide SVG 图标

    • /_shared/ 下的共享库（全部离线可用，禁止走 CDN）：

      文件 库 用途
      echarts.min.js ECharts 5.5 图表，与图表资产同版本
      tailwind.js Tailwind CSS 4（浏览器版） 原子类样式，<script src> 引入即生效
      daisyui.css、daisyui-themes.css daisyUI 5 按钮、卡片、模态框、标签页等现成组件，依赖 tailwind.js；主题需另引 daisyui-themes.css
      alpine.min.js Alpine.js 3 用 x-data / @click 写交互，免手写 DOM 操作（用 defer 引入）
      gsap.min.js、ScrollTrigger.min.js GSAP 3 时间线、进入/移动/缩放动画，滚动触发
      aos.js、aos.css AOS 2.3 元素滚动进入时淡入、滑入、缩放（data-aos），需调用 AOS.init()
      lenis.min.js、lenis.css Lenis 平滑滚动
      countUp.umd.js CountUp.js 2 数字滚动动画
      dayjs.min.js Day.js 1 日期时间格式化 
      <link rel="stylesheet" href="/_shared/daisyui.css">

<button class="btn btn-primary">启动</button>
  • 已有文件不覆盖：目标文件已存在时保持不变。资源未完整写入时，后续再次读取 Web 目录会继续补全
  • 共享库：_shared/ 用于存放 Web 页面可直接引用的第三方库。默认库随 DataMaster 提供，也可用于存放 Agent 创建页面所需的其他离线依赖，无需通过 CDN 加载
  • 目录约定：_sdk/ 和 _shared/ 为系统资源目录，请勿手动修改 DataMaster 提供的文件
  • 工程随行：_sdk/ 和 _shared/ 会随 Web 工程目录一起复制
  • 资源检索：图标仍可通过 dynamicViewWeb.icons 查询名称和标签

变量网关

IDynamicViewWebGateway 是 Web 前端访问变量的唯一入口：读取来自变量中心，写入一律经过 IDynamicViewVariableWriteService，从不直接修改变量缓存或访问通讯协议。网关与传输层无关（IDynamicViewWebConnection），生产环境由 WebSocket 适配。

连接生命周期

客户端连接 /ws/dynamic-views
    ↓
hello（页面路径、登录令牌、宿主联动令牌）   10 秒内未握手则关闭
    ↓
读取清单并逐个解析变量，确定登录身份
    ↓
welcome（变量元数据、登记页面、权限、当前用户、运行状态）
    ↓
subscribe → snapshot（完整快照）
    ↓
patch（增量）… write → writeResult … login / logout → auth …

快照与增量

  • 首次订阅返回完整快照；之后只推送变化的字段。
  • 变量变化按 50 ms 合并，同一字段在一个周期内只推送最新值，避免高频通讯轮询产生大量消息。
  • snapshot 与 patch 共用按连接递增的序号，客户端发现断档时发送 resync 取回完整快照。
  • 发送队列有界：客户端消费过慢时丢弃增量，下一周期改发完整快照；控制类消息（回执、错误）无法入队时断开连接（关闭码 4008）。
  • 运行时尚未写入的字段在变量中心里是文本形式的默认值，网关按字段类型转换后发送；NaN、±∞ 以 null 发送。

写入流程

write { 别名: 值 }
    ↓
按宿主账号刷新登录身份（角色降级、账号删除立即生效）
    ↓
逐个检查：已声明 → 可写 → 值类型（布尔/数字/字符串）→ 角色
    ↓
按结构体分组，同一结构体的字段合并为一次 TryWriteStructureAsync
    ↓
写入服务：结构体/字段检查 → 类型转换 → 读写权限 → 通讯通道 → PLC 写入 → 提交变量中心
    ↓
writeResult（成功或稳定错误码）+ 记入操作日志
    ↓
变量中心 ValueChanged → 所有客户端收到新值

客户端以变量中心再次广播的值作为最终可信状态；写入失败时界面回到服务端的值，不会显示未成功写入的值。写入属于用户意图，客户端断开不会取消已发出的写入。

重新连接

关闭码 场景 客户端行为
4100 结构体定义变化、切换或新建工程、manifest.json 内容变化（只改格式或注释不算） 立即重连，重新读取清单
1001 服务停止 显示断开，按退避间隔重连
4004 工程没有 Web 清单 停止重连并报错
4000 协议错误 停止重连并报错
4008 客户端消费过慢 重连
4029 连接数超过上限（全局或同一地址） 按退避间隔重连
4401 被 DataMaster 管理员在面板“在线客户端”中断开（独立登录的令牌同时注销） 停止重连，lastError 提示刷新页面；刷新后可重新进入（需重新登录）

变量写入服务

为支持 Web 与组态视图并发写入，IDynamicViewVariableWriteService 做了两项与前端无关的改进，组态视图同样受益：

带错误码的写入结果：新增 TryWriteFieldAsync / TryWriteStructureAsync，返回 DynamicViewVariableWriteResult。原有返回 bool 的方法保留，内部改为调用新方法；接口提供默认实现，已有的实现与测试替身无需修改。

错误码 协议错误码 说明
InvalidArgument INVALID_ARGUMENT 结构体或字段标识为空
StructureNotFound STRUCTURE_NOT_FOUND 结构体不存在
StructureDisabled STRUCTURE_DISABLED 结构体已停用
FieldNotFound FIELD_NOT_FOUND 字段不存在
ReadOnly READ_ONLY 结构体只读或为系统结构体
TypeMismatch TYPE_MISMATCH 写入值与字段类型不匹配
NoWritableChannel NO_WRITABLE_CHANNEL 未关联可写通讯通道
DeviceWriteFailed DEVICE_WRITE_FAILED 通讯设备写入失败

按结构体串行化：单字段写入最终是整结构体写入。“读取当前值 → 合并 → 写设备 → 提交”整段在同一把结构体锁内完成，避免多个写入方同时修改同一结构体的不同字段时后写者覆盖先写者；不同结构体之间互不阻塞。

Warning

变量中心的 ValueChanged 在结构体锁内同步触发。事件处理器中不要同步等待（.Wait()、.Result）对同一结构体的写入，否则会死锁；需要连锁写入时请异步发起。

权限与登录

Web 视图不维护独立账号，直接使用 DataMaster 用户与角色（none < visitor < operator < engineer < admin，developer 拥有全部权限），判定规则与组态视图相同（HasRole）。

权限判定

操作 所需角色 默认
读取（订阅）变量 max(auth.viewRole, 变量 readRole) 任何人可读
写入变量 max(auth.writeRole, 变量 writeRole) 操作员及以上

权限由网关在每次订阅与写入时强制执行。页面级 viewRole 只驱动 SDK 的登录引导与导航显示——客户端可以自行声称所在页面，因此它不是安全边界，敏感数据与危险操作应通过变量或应用级角色保护。

未登录返回 LOGIN_REQUIRED，已登录但角色不足返回 FORBIDDEN。登出或降级后，已无读取权限的订阅会被撤销并通知客户端。

登录方式与宿主同步

宿主联动会话 独立会话
场景 DataMaster 内打开的新窗口 / 无边框窗口 浏览器、局域网终端
身份 始终等于 DataMaster 当前登录用户 用 DataMaster 账号单独登录
页面内登录 / 登出 即 DataMaster 登录 / 登出 只影响该浏览器标签
DataMaster 切换用户 所有联动窗口立即跟随 不受影响
角色变更、账号删除 随宿主 写入前与每 30 秒同步（同一账号的查询结果复用 2 秒，最多延迟 2 秒生效）
有效期 随宿主 8 小时滑动，服务停止即失效；默认同一浏览器所有标签页共享（localStorage），loginScope: "tab" 时仅当前标签页

宿主联动通过窗口地址中的一次性令牌（dvHost）建立：令牌只在本机连接时生效，SDK 读取后存入会话存储并从地址栏移除，站内跳转保持联动；局域网客户端即使拿到令牌也按独立会话处理。

独立会话的登录不会切换 DataMaster 当前用户：认证服务新增了只校验不登录的 VerifyCredentialsAsync，以及用于同步账号数据的 FindUserAsync。

审计与防护

  • 每次 Web 写入记入操作日志：ActionNamespace 为 MAS.DynamicViews.Web，ActionMethod 为页面路径，Description 为写入的别名与值，未登录写入记为 anonymous@地址
  • Web 登录记入登录日志，备注为 web-login / web-login-failed
  • 同一客户端地址连续 5 次登录失败，或同一用户名（不论来自哪台终端）累计 10 次失败，锁定 1 分钟（LOGIN_LOCKED）；15 分钟内没有再失败的记录作废并清理
  • 账号库查询失败返回 AUTH_UNAVAILABLE，不计入失败次数
  • 把访问模式切换为局域网需要宿主当前用户为管理员（DynamicViewWebSettings.LAN_ACCESS_ROLE）：面板上非管理员选择"局域网"会被恢复为已保存的设置；Agent 只能通过需要用户确认的 dynamicViewWeb.host.enableLan 开放局域网
  • SDK 在页面离开（pagehide）时主动关闭连接，从前进/后退缓存恢复（pageshow）时重连；预渲染中的页面（document.prerendering）等到真正显示后才连接。否则部分浏览器（如 Edge）会让离开的页面继续占着连接，直到浏览器丢弃缓存
  • 面板上的“在线客户端 N”可点击，弹出当前连接列表（用户与角色、宿主联动/Agent 验证标记、地址、页面、连接时间）；管理员可逐个“断开”：连接以 4401 关闭，独立登录的会话同时注销令牌（同一浏览器共享该令牌的其他标签页随之失去登录）
Note

局域网访问默认使用明文 HTTP / WebSocket，账号密码在局域网内以明文传输。部署在不可信网络时请启用“局域网 HTTPS 加密”，并配合 IP 白名单或网络隔离。

开启 HTTPS、启用/修改白名单与开放局域网同级，需要宿主当前用户为管理员；Agent 没有修改这两项的工具入口（dynamicViewWeb.current 只读展示当前值）

图标

内置 Lucide 完整图标库（lucide-static 1.48.0，ISC 许可，2000+ 个），作为嵌入资源随应用发布，完全离线：

  • 页面使用 <i data-dv-icon="gauge"></i>，SDK 从工程里的 /_shared/icons/{name}.svg 按需加载并缓存，不会整体下发
  • Agent 用 dynamicViewWeb.icons 按英文名称与标签搜索图标
  • Lucide 没有的图标，可以在共用文件中自行绘制内联 SVG

引用检查

Web 清单通过 IDynamicViewReferenceContributor 纳入 IDynamicViewReferenceService。被 Web 视图引用的结构体不可删除，字段不可修改类型，与组态视图控件绑定保持一致的引用保护。数据中心和 Agent 工具中的引用提示显示为“Web 视图：标题 / 变量：别名”。

清单存在但无法解析时（如 Agent 尚未完成编辑），改为在 manifest.json 原文中匹配结构体和字段标识，匹配到即视为存在引用，并提示“Web 视图：manifest.json（无法解析）”。宁可误报也不漏报，避免误删仍被页面使用的结构体；修复清单后重新检查即可

DataMaster 界面

动态视图页面的工具栏提供「组态视图 | Web 视图」切换。切换只改变页面中显示的内容，两套前端共用变量中心与通讯运行时，运行互不影响。

在新窗口与无边框窗口中打开的页面是宿主联动会话；在浏览器中打开的页面是独立会话。

Agent 工具

Web 视图使用独立的 dynamicViewWeb.* 工具，与组态视图的 dynamicViews.* 分开；页面文件由 Agent 用 CLI 直接编写。Agent 端技能为 mas-dynamic-views-web。

当前能力边界

  • 服务端依赖 DataMaster 进程，不能独立部署
  • 局域网 HTTPS 使用自签名证书，终端首次访问需手动信任
  • 不支持导入现场自有证书，也没有 HTTP 到 HTTPS 的自动跳转
  • 独立登录的令牌保存在内存中，服务停止或 DataMaster 重启后需要重新登录
  • 页面级 viewRole 不限制静态文件访问，数据保护依赖变量级角色
  • 没有 Web 可视化设计器，页面由 Agent 或开发者直接编写
  • 后端查询目前只接入 MySQL 驱动；查询结果一次性返回，没有实时推送、分页游标和流式传输
  • 数据源密码使用应用内置密钥加密（与现有数据库配置一致），能防止直接看到明文，但不等同于机密管理；对安全要求高的现场请使用权限受限的只读账号
