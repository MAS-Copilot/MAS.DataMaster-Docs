MAS.VisionFlow

MAS.VisionFlow 提供视觉流程的图模型、设计器、节点与运行时。MAS.DataMaster 只提供视觉工作台的页面外壳、依赖注入注册与宿主服务 IVisionFlowHost（代码编辑器、调试输出、确认框）的实现；视觉算法保留在 MAS.Vision

分层结构

MAS.VisionFlow
├─ Designer/        通用设计器内核
│  ├─ Graph/        FlowGraph · FlowNode · FlowPort · FlowEdge · FlowPortType
│  ├─ FlowDesigner  唯一编辑入口：增删节点、连/断线、移动、复制粘贴、撤销重做
│  ├─ History/      撤销动作（快照式，默认 100 步）
│  ├─ Canvas/       FlowCanvas · FlowEdgeLayer · FlowNodeCard · FlowPortView · FlowMinimap
│  ├─ Tools/        平移缩放、框选、拖动、拉线、键盘、拖放
│  └─ Library/      FlowNodeDescriptor · 模块菜单
├─ Nodes/           视觉节点、卡片主体、设置视图
├─ Runtime/         管道划分、执行器、循环运行器、脚本处理器
├─ Persistence/     VisionFlowDocument（内存模型）· 清单 + 内容目录读写
└─ Views/           工作区（模块菜单 + 画布 + 管道面板）、设置窗口、输出查看窗口

架构约定：

  • 子系统内部不使用 IEventAggregatorService。编辑统一经过 FlowDesigner，卡片按钮发送路由命令（FlowCommands），画布处理编辑类命令，运行、设置与输出查看交由宿主处理。
  • 窗口（节点设置、端口输出查看）一律通过宿主注册的 IWindowsProviderService 打开，以复用应用统一的模态遮罩与开关音效。

节点模型

VisionNode 派生自 FlowNode，同时是图模型与运行时对象，卡片视图只负责呈现。

  • 端口：构造函数中通过 AddInput / AddOutput 声明，类型为强类型 FlowPortType；拉线时按类型、方向、重复、环路与锁定状态校验，失败原因见 FlowConnectionError
  • 设置：带 [JsonProperty] 的属性即节点设置，随工程文件保存，参与撤销重做与复制粘贴，属性变化会将工程标记为已修改
  • 资产与脚本：模板图、金样、图像源副本这类大块二进制数据不放设置，重写 SaveAssets / OnLoadAssets（键是文件名，如 golden-mean.png），工程里每项一个文件；脚本源码重写 SaveScript / OnLoadScript，工程里加密存储。资产数组按不可变使用，数据没变就返回同一个数组，保存据此跳过。资产随快照参与撤销与复制粘贴，变化时须自己调 NotifySettingsChanged() 标脏
  • 执行：逻辑实现于 ExecuteAsync(VisionExecutionContext)，GetInput<T> 取输入、SetOutput 写输出、ReportStatus 上报警告等状态；输入仅在本次执行内有效，需要跨执行保留时必须 Clone
  • 图像预览：VisionPreview 由执行线程调用 Offer(mat)，仅到点时复制（可见处约 15 帧/秒，不可见处约 1 帧/秒，默认缩小到最长边 1280 像素），界面线程写入复用的 WriteableBitmap；视图通过 nodes:VisionPreviewBinding.Source 绑定，控件不可见时自动降频
  • 状态与刷新：节点状态为 FlowNodeStatus，颜色与文本由 FlowNodeStatusToBrushConverter、FlowNodeStatusToTextConverter 统一给出（文本走语言键 FlowNodeStatus*，支持中/繁/英）。连续运行时节点耗时与管道统计每 100 ms 最多推送一次界面，实时值保留在 LatestElapsedMilliseconds 与 VisionRunResult，单次触发与停止时立即刷新；“运行中”指示延迟 200 ms 显示，避免快速节点状态跳动
  • 资源释放：相机、后台任务、脚本等资源在 ReleaseResources 中释放，节点被删除时调用

输出所有权（视觉性能的关键）：节点写入输出的方式决定释放责任

方法 语义 释放责任
SetOutput 借出：节点自身持有的值，或直通的上游输入 框架不释放
SetOwnedOutput 移交：本次新建的 Mat 等可释放对象 下一次产出时由后台线程释放，执行失败或节点删除时立即释放
GetOutputBuffer 复用缓冲：每个端口两块 Mat 交替，作为 OpenCV 输出参数写入（如 Cv2.CvtColor(src, buffer, code)） 尺寸不变时不再分配，正在发布的那一块不会被写入

界面线程读取输出（查看窗口、预览）必须走 ReadLastOutput，在同一把输出锁内完成转换与格式化。

节点参数

[ObservableProperty]
[property: JsonProperty]
[property: VisionParameter("BlockSize", DescriptionKey = "BlockSizeDescription", Minimum = 3, Maximum = 201, IsOddOnly = true, Unit = "px")]
private int _blockSize = 31;

嵌套配置对象（类型在 MAS.Vision，不引用本特性）的成员标注在节点类上并给出路径：

[VisionParameter("FilePath", Path = "ImageSourceModel.FilePath")]
public sealed partial class ImageSourceNode : VisionNode { ... }
组成 作用
VisionParameterAttribute 名称与说明的语言键（与界面标签一致）、范围、单位、奇数约束、候选值来源、成员路径；标在 ICommand 属性上表示可调用的操作
VisionParameterSchema 反射生成 VisionParameterDescriptor（名称、取值形态、范围、枚举值、是否保存、是否只读），Read 读取，TryWrite 按类型转换并校验范围、奇数、枚举名与候选值，InvokeAsync 等待操作执行完成
  • 带 OptionsSource 的枚举只接受方法返回的值（如颜色转换只开放列表里的转换码）；文本参数的候选值只作提示（如资源键）
  • 选择对象型的设置（如模板匹配的 SelectedMatchMode）另加一个枚举代理属性供 Agent 读写，不随工程保存
  • 单元测试会检查全部节点的参数名称与说明都有词条

新增节点：算法放在 MAS.Vision（写入调用方给的 dst，可单独测试），节点类声明端口、给 Agent 开放的属性加 [VisionParameter]、实现 ExecuteAsync，手写卡片主体（及需要时的设置页）后在 VisionNodeCatalog 中注册描述符。定位类节点继承 VisionLocateNode：输出 0 原图直通、输出 1 定位结果，构造函数末尾调用 AddAnnotatedOutput() 把标注图端口放在最后一个输出。

原图与标注图

  • 算法只计算不绘制，标注统一用 MAS.Vision.LocateAnnotator（线宽、字号随图像尺寸自动缩放，不提供样式参数）
  • 图像输出原样直通输入（不复制），下游算法接它拿到的永远是干净的图；标注图是单独的端口类型 vision.annotatedImage，只能连到图像查看这类 vision.displayImage 输入，不能当算法输入
  • 标注图按需绘制（VisionExecutionContext.PublishAnnotation）：管道未启动（单次运行、调试）时总是画；管道启动后只在标注图端口有连线、或打开了端口查看窗口（VisionNode.WatchOutput）时才画
  • 模板匹配、颜色识别、姿态解算同样有标注图端口（在最后）；姿态解算的标注画在参与解算的图上（开启去畸变时为去畸变后的图）

工作区外观

  • 卡片左上角与设置窗口标题使用所属一级分类的图标（双色渐变），模块菜单的二级条目统一使用组件图标
  • 端口圆点按数据类型使用低饱和类型色，连线统一为中性色（VisionFlowEdgeBrush），选中态使用强调色
  • 深色主题为近黑色板（画布 #111113，节点与面板 #18181B），画刷集中定义于 MAS.Dark.xaml / MAS.Light.xaml 的 VisionFlow* 资源键；顶部操作栏、模块菜单与状态栏使用 ui:Card，画布外框绘制圆角底色并裁剪内容

节点状态色：

状态 含义 颜色
Idle 空闲，尚未初始化或运行 灰 #71717A
Ready 初始化完成 青 #14B8A6
Running 一次执行正在进行 蓝 #3B82F6
Success 执行成功 绿 #22C55E
Warning 执行完成但有警告 琥珀 #F59E0B

InitFailed 初始化失败 紫 #A855F7
Looping 后台循环运行中（脚本执行、位姿生成） 绿，主题 OnlineBrush，与管道运行同色

渲染与性能

  • 节点位置通过 TranslateTransform 变换，拖动过程不触发布局重算
  • 连线由 FlowEdgeLayer 承载，每条线一个 DrawingVisual，只重绘受影响的连线
  • 卡片不使用 DropShadowEffect 等位图特效
  • 视口外（保留一屏余量）的卡片不参与渲染，内容边界由模型计算
  • 位图缓存默认关闭（“更多”菜单可开关）：缩放小于 1.2 时卡片栅格化，RenderAtScale 跟随缩放，停手后按新比例重新栅格化
  • FlowMinimap 在 OnRender 中直接绘制节点方块、视口外遮罩与视口框，不创建可视元素；绘制合并到下一帧，拖动时冻结映射，避免小地图自身跳动

持久化

工程类型为 VisionFlow，工程是一个文件夹：.masproj 里只有清单 ServiceData["VisionFlowManifest"]（格式版本），内容按文件存在工程目录下（布局见 VisionFlowProjectPaths）：

文件 内容
Flow.json 节点快照（不含资产与脚本）、连线、管道（标识、名称、归属节点；改过且仍有节点在画布上的脱离管道也保存），明文
Resources.json 资源，明文
Scripts/Pipelines/管道标识.mscript 管道脚本，IEncryptionService.Encrypt 加密（调试版也加密）
Scripts/Nodes/节点标识.mscript 节点脚本（SaveScript / OnLoadScript），加密
Assets/节点标识/ 节点资产（SaveAssets / OnLoadAssets），原样存放
  • 运行时与持久化之间按 VisionFlowDocument 交接（IVisionFlowPersistenceService.GetDocument/SetDocument）；保存时运行时先在 ProjectSaving 里交回文档，持久化服务再落盘
  • 保存是增量的：JSON 与脚本按明文内容指纹、资产按数组引用判断，没变的不重写；删掉的节点、管道对应的文件随之删除
  • 内容读取在 OnBeforeProjectApplied 完成，文件缺失、脚本无法解密时拒绝打开，当前工程不受影响
  • 另存为与动态视图一致：工作台整目录复制，持久化服务补齐缺失项并整份重写
  • 自 v3.27.0 起旧版 ImageProceFlow 工程不再兼容

加载时无法识别的节点类型或无法建立的连线不会导致工程加载失败，而是记入 VisionFlowRuntime.LoadErrors 并给出提示。

对外接口

IVisionFlowRuntime 以单例注册，不依赖工作台页面是否打开，工程加载后即可由动态视图脚本、Agent 等外部触发。

成员 说明
IsProjectLoaded 是否已加载视觉工程
Pipelines 当前全部管道
FindPipeline(name) 按名称查找管道（不区分大小写），找不到返回 null
TriggerAsync(name, token) 执行一次管道（未初始化时先初始化）；节点失败不抛异常，找不到管道抛 PipelineNotFoundException
StartAsync / StopAsync / StopAllAsync 启动与停止管道循环
GetNodeResult(nodeTitle) 节点最近一次执行结果（标题不区分大小写），不存在或尚未执行返回 null
RunCompleted、PipelineStateChanged 管道执行完成、运行状态变化事件（可能在任何线程触发）

管道循环间隔由管道脚本的 FixedIntervalMs 决定，默认 100 ms；取 0 时跑完立即进入下一轮（连续运行，占满一个线程）。受 Windows 计时精度（约 15.6 ms）限制，取值 1~15 的实际间隔约为 16 ms。

Agent 工具

视觉工作台向 Agent 提供 visionFlow.* 工具。逻辑在 MAS.VisionFlow/Agent/VisionFlowAgentService（可单元测试），宿主 MAS.DataMaster/NamedPipeIpc/VisionFlow/VisionFlowToolProvider 只做参数解析与结果序列化；工作流说明在 Skill mas-vision-flow。

工具 风险 职责
visionFlow.status Low 工程是否打开、画布是否锁定、管道与资源键
visionFlow.nodeTypes Low 节点类型目录（含端口）；指定类型时返回参数架构
visionFlow.graph.get Low 全部节点（含卡片实际尺寸）、连线、管道与重叠的卡片；指定节点时返回端口连接、参数当前值与最近结果
visionFlow.graph.apply Medium 按顺序批量执行 add / connect / disconnect / set / rename / move / layout，结果附新节点边界与重叠的卡片
visionFlow.canvas.view Low 离屏截取画布（不受用户当前视口影响），附各卡片边界与重叠，供 Agent 检查布局
visionFlow.node.delete High 删除节点及其连线
visionFlow.node.invoke Medium 调用节点操作（如示教对位的「设为基准」）
visionFlow.run Medium 执行管道或运行到节点，返回各节点结果，可附带端口输出图像（JPEG，按长边缩放）
visionFlow.pipeline.control Medium 初始化、启动循环、停止、重命名管道
visionFlow.script.get Low 管道脚本（LF 换行）、指纹、处理器类名，以及管道内各节点可读取的结果键（C# 类型、说明、最近值）
visionFlow.script.edit Medium 修改管道脚本：edits 精确替换 / code 整体重写 / reset 恢复模板，三选一；写入前编译检查，成功后回显改动处（带行号）
visionFlow.script.test Medium 不启动循环试跑脚本一轮：执行管道 → HandleResultAsync → CompleteAsync，返回本次调用的 Debug.Enqueue 输出与脚本异常
  • 编辑走工作区的 FlowDesigner，与界面共用撤销历史：一批操作在设计器历史的批量模式中执行，全部成功合并为一步撤销，任一失败逆序回滚且不留重做记录；参数写入记为 SetParameterHistoryAction，同样可撤销
  • 画布锁定时拒绝编辑；运行中的管道结构锁定，参数仍可修改；参数改动后所在管道下次执行先重新初始化
  • 图与参数只在 UI 线程读写（VisionDispatcher），执行在后台线程；附带图像在节点输出锁内编码，避免缓冲被下一次执行复用
  • 改动只在内存中，由用户保存工程
  • 管道脚本只在内存里，没有文件可给 CLI 工具编辑，因此按 oldText → newText 局部替换，不必每次传整份脚本：匹配与换行符无关（写回保留原换行风格）；先在后台编译检查（不加载程序集、不替换正在用的处理器），有错误整批不生效，错误给出改后脚本的行号与该行原文；改了命名空间或处理器类名直接拒绝；运行中的管道拒绝修改
  • 脚本按“节点标题 + 结果键”取值，读取与编辑时按字符串字面量检查引用（跳过整行注释），标题或键对不上的列入 referenceWarnings；graph.apply 改名后仍按旧标题取值的脚本列入 scriptWarnings。只报告不拦截
  • 试跑与循环共用编译缓存里的处理器，语义同循环一轮（执行失败不调用 CompleteAsync），默认跳过 TriggerSignalAsync。输出靠 Debug.BeginCapture：按 AsyncLocal 只收本调用链的消息，其他管道循环同时输出不会混入，消息照常进输出窗口。脚本的副作用（写 PLC 等）是真实的
  • 布局按卡片实际尺寸计算（FlowCanvas.MeasureNodeBounds，新卡片先同步布局一次）：add 省略坐标时，整批完成后整组新建的流程按连线从左到右分列排布，接入已有流程的新节点放到上游右侧（或下游左侧）不压住别的卡片；layout 操作排布整个画布或某条流程。移动记入同一步撤销

新增节点时 Agent 层不用改代码：给要开放的属性加 [VisionParameter]（嵌套配置在类上按路径声明），工具即可描述、校验和读写；端口由节点构造函数声明，工具自动读取。

后续规划

与动态视图（DV）的集成在后续版本提供：将 IVisionFlowRuntime 注入 DV 全局脚本，由运行界面通过变量、脚本触发管道，并通过订阅 RunCompleted、PipelineStateChanged 的发布器把节点状态与结果发布到运行界面。
