WebView 事件与审批

MAS.PrismaAgent 的对话 UI 由 WPF 后端通过 WebView 驱动，普通回复、Agent timeline、审批与计划交互统一在同一个对话界面中呈现

后端调用前端

会话事件

聊天内容统一通过 IConversationJournal 下发，前端只保留：

  • applyConversationEvent(evt)

作为聊天内容唯一入口。

负责：

  • 实时消息展示
  • 历史事件重放
  • Agent timeline 更新
  • 文本流更新
  • 工具执行状态展示

实时事件和历史重放必须走同一套处理逻辑

直接 UI 桥接

非聊天历史内容仍通过 WebView 直接调用前端

主要包括：

  • 会话重放开始与结束
  • 清空会话
  • 恢复输入草稿（连同随之退回的附件）
  • 新导入附件的回推
  • 临时聊天状态
  • 发送状态
  • Toast
  • 主题切换
  • 会话侧栏
  • 审批卡片
  • 计划卡片

这些状态不进入会话事件日志

会话事件日志

IAgentEventSink 和 IConversationStreamView 不直接执行 JavaScript，而是将展示事件写入 IConversationJournal。

IConversationJournal 负责：

  • 实时派发事件
  • 持久化展示历史
  • 保证事件顺序
  • 为历史重放提供数据

核心约束：

  • 实时与重放使用同一个 applyConversationEvent
  • 重放使用事件原始时间
  • 重放只恢复展示，不重新执行模型或工具
  • 编辑历史通过追加截断事件表达，不直接删除原事件

前端调用后端

前端通过 window.chrome.webview.postMessage 将用户操作回传给 WPF 后端。

主要操作包括：

  • 发送消息
  • 停止生成
  • 新建会话
  • 编辑最后一条消息
  • 切换或重放会话
  • 切换临时聊天
  • 获取会话列表
  • 删除会话
  • 重命名会话
  • 切换高风险工具的审批策略
  • 上传文件
  • 提交审批结果
  • 提交计划交互结果

MainViewModel 统一接收并分发这些消息

Agent Timeline

Agent timeline 用于展示实际发生的 Agent 行为，例如：

  • 工具调用
  • 工具执行结果
  • 资源读取
  • 审批
  • 观察结果
  • 轮次完成

普通文本问答不显示完整 timeline。

Timeline 本质上仍属于会话展示事件，由 applyConversationEvent 统一处理

审批

高风险工具执行前由后端审批服务发起审批请求。

流程：

  • 后端判断工具风险
  • 后端生成审批请求
  • WebView 展示审批卡片
  • 用户选择允许或拒绝
  • 前端回传审批结果
  • 后端决定是否继续执行工具

审批状态属于临时交互状态，不进入会话事件日志

前端职责边界

WebView 只负责：

  • 展示
  • 用户输入
  • 用户审批选择
  • 用户交互结果回传

后端负责：

  • 风险判断
  • 参数校验
  • 工具路由
  • 工具执行
  • 会话状态
  • 历史记录
  • 模型上下文

安全与执行逻辑始终保留在后端，WebView 只承担展示和交互职责
