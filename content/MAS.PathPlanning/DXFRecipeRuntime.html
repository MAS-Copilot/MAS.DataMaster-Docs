图纸配方运行时

一个工程可关联多个图纸配方（一张 DXF 图纸 = 一个配方）。本文说明运行期换产的分层边界、配方激活事件，以及后台脚本与下位机的交互约定

分层边界

配方状态只有一个所有者：DXFTrajectoryPersistenceService。它同时实现两个接口，按调用方能力裁剪暴露面

接口 能力 所有者
IDXFRecipeRuntimeService 查配方、激活配方、设置图层、跨配方只读取数、订阅激活事件 后台脚本（按需）
IDXFTrajectoryPersistenceService 上面的全部，外加配方增删改、更换图纸、写轨迹与参数、落盘、脚本代码 上位机界面、后台脚本

两个接口在 DI 中转发到同一个单例，配方状态不会分叉：

services.AddSingleton<IDXFTrajectoryPersistenceService, DXFTrajectoryPersistenceService>();
services.AddSingleton<IDXFRecipeRuntimeService>(provider => provider.GetRequiredService<IDXFTrajectoryPersistenceService>());

配方激活

SwitchRecipeAsync 带来源参数，来源决定两件事：

Task<bool> SwitchRecipeAsync(
    string recipeCode,
    ActivationSource source = ActivationSource.Ui,
    CancellationToken token = default);
来源 把工程标脏 界面报错方式
Ui 是，切配方是用户对工程的编辑 模态对话框
Script 否，下位机换产是生产行为，每次都标脏会让工程长期处于未保存状态 轻提示
Agent 否 轻提示

激活成功后触发 RecipeActivated，事件参数带 Entry、RecipeCode、Source、PreviousRecipeCode

界面订阅它实现自动跟随：下位机呼叫配方 → 脚本激活目标配方 → 界面换成该配方的图纸与图层。三种来源共用同一套跟随逻辑，界面自己切换时也不再单独刷新，避免两条路径行为漂移

// PathPlanningWorkbenchViewModel
_dXFTrajectoryPersistence.RecipeActivated += DXFTrajectoryPersistence_RecipeActivated;

private void DXFTrajectoryPersistence_RecipeActivated(object? sender, RecipeActivatedEventArgs e) {
    _ = DispatchToUiAsync(() => FollowActivatedRecipeAsync(e));
}

事件可能在任意线程触发，UI 订阅方必须自行封送到调度器，且不要在处理程序里同步等界面渲染完成，否则会把脚本响应下位机的节拍一起拖住

图层激活

换产后轨迹区是空的，下位机接着指定要加工哪个图层，界面把轨迹区切过去，这样从界面上就能看出下位机当前在做哪个配方的哪个图层

bool ActivateLayer(string layerName, ActivationSource source = ActivationSource.Script);
  • 作用域是当前配方，换产后上一个配方的图层名会被拒绝
  • 只认已生成轨迹的图层：轨迹一律由界面手动生成，这里拿不到就返回 false 且不触发事件，绝不顺手生成
  • 不写任何持久化数据，纯运行期指定，因此不带 async，也不会把工程标脏
  • 成功后触发 LayerActivated（带 RecipeCode、LayerName、Source），界面据此把轨迹区切到该图层

脚本拿到 false 就把该任务判为失败，由业务层定是报警还是跳过该图层

换产刷新与设置图层可能连着来。界面在换产刷新完成前收到图层激活会先挂起，等图层卡片重建完再切过去，避免切到还没渲染出来的图层上

回读当前状态

设置了什么就能读回什么，脚本不必自己再存一份，也方便回写给下位机：

读 对应的设置
DxfRecipeEntry? GetCurrentRecipe() SwitchRecipeAsync
string? GetCurrentLayer() ActivateLayer
TrajectoryPath? GetCurrentTrajectory() 当前配方 + 当前图层的轨迹，省掉自己拼编号与图层名

当前图层挂在配方工作区上，换产时工作区整个换掉，图层随之回到未激活，不存在跨配方残留。它只反映 ActivateLayer 设置的图层，界面手动点开某个图层的轨迹不会改变它——这里要回答的是"下位机在做哪个图层"，不是"操作员在看哪个图层"

点位下发

轨迹点与扩展点转成下位机可直接整段写入的定点整数：

// 六个位姿分量与点位类型各占一段连续数组
var buffer = trajectoryPath.ToPointBuffer(capacity: MAX_POINT_COUNT);
if (buffer.IsTruncated) {
    // 点数超出下位机点位区，判任务失败，不能只发一半就让设备走
}

await _mcProtocol.WriteWordsAsync("D", BASE_ADDR + 1650, buffer.X, token);
// ……Y / Z / Rx / Ry / Rz / Types 同理

// 单个扩展点按 X、Y、Z、Rx、Ry、Rz 顺序取六个整数，已叠加各自偏移量
await _mcProtocol.WriteWordsAsync("D", BASE_ADDR + 1616, extendedPoint.ToFixedPointPose(), token);
  • capacity 传下位机点位区的固定点数，多余位置补 0，下位机据此清掉上一层遗留的尾巴；传 0 则按实际点数分配
  • 默认取相对坐标、缩放 1000（毫米转微米、度转千分之一度），都可以改
  • 取整是先乘再四舍五入。反过来先按小数位取整再乘会踩二进制小数的坑：1.001 会变成 1000.999…，直接截断就少一个最小单位
  • 缩放后超出 32 位整数会抛 OverflowException，宁可失败也不能让数值回绕把设备开到错误位置

数据存储布局

工程根目录/
├── 工程名.masproj              # 配方索引 + 标定索引 + 脚本（工程级）
├── Calibrations/               # 标定数据，工程级共用，可被多个图纸配方绑定
└── Recipes/
    ├── R001/                   # 文件夹名 = 配方编号
    │   ├── layers/
    │   │   ├── 图层A.json      # 单图层完整 TrajectoryPath（含扩展点）
    │   │   └── 图层B.json
    │   ├── generations/        # 各图层的生成记录，供生产追溯
    │   └── parameters.json     # 该配方各图层的轨迹生成参数
    └── R002/
        └── ...

图层轨迹 JSON 以图层名命名（非法文件名字符替换为 _ 并追加 8 位哈希），文件内容的 Name 字段才是权威图层名
