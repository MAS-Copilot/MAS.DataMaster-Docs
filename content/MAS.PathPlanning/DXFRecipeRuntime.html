图纸配方运行时

一个工程可关联多个图纸配方（一张 DXF 图纸 = 一个配方）。本文说明运行期换产的分层边界、配方激活事件，以及后台脚本与下位机的交互约定

分层边界

配方状态只有一个所有者：DXFTrajectoryPersistenceService。它同时实现两个接口，按调用方能力裁剪暴露面

接口 能力 所有者
IDXFRecipeRuntimeService 查配方、激活配方、设置图层、跨配方只读取数、订阅激活事件 后台脚本（按需）
IDXFTrajectoryPersistenceService 上面的全部，外加配方增删改、更换图纸、写轨迹与参数、落盘、脚本代码 上位机界面、后台脚本

两个接口在 DI 中转发到同一个单例，配方状态不会分叉：

services.AddSingleton<IDXFTrajectoryPersistenceService, DXFTrajectoryPersistenceService>();
services.AddSingleton<IDXFRecipeRuntimeService>(provider => provider.GetRequiredService<IDXFTrajectoryPersistenceService>());

配方激活

SwitchRecipeAsync 带来源参数，来源决定两件事：

Task<bool> SwitchRecipeAsync(
    string recipeCode,
    ActivationSource source = ActivationSource.Ui,
    CancellationToken token = default);
来源 把工程标脏 界面报错方式
Ui 是，切配方是用户对工程的编辑 模态对话框
Script 否，下位机换产是生产行为，每次都标脏会让工程长期处于未保存状态 轻提示
Agent 否 轻提示

激活成功后触发 RecipeActivated，事件参数带 Entry、RecipeCode、Source、PreviousRecipeCode

界面订阅它实现自动跟随：下位机呼叫配方 → 脚本激活目标配方 → 界面换成该配方的图纸与图层。三种来源共用同一套跟随逻辑，界面自己切换时也不再单独刷新，避免两条路径行为漂移

// PathPlanningWorkbenchViewModel
_dXFTrajectoryPersistence.RecipeActivated += DXFTrajectoryPersistence_RecipeActivated;

private void DXFTrajectoryPersistence_RecipeActivated(object? sender, RecipeActivatedEventArgs e) {
    _ = DispatchToUiAsync(() => FollowActivatedRecipeAsync(e));
}

事件可能在任意线程触发，UI 订阅方必须自行封送到调度器，且不要在处理程序里同步等界面渲染完成，否则会把脚本响应下位机的节拍一起拖住

图层激活

换产后轨迹区是空的，下位机接着指定要加工哪个图层，界面把轨迹区切过去，这样从界面上就能看出下位机当前在做哪个配方的哪个图层

bool ActivateLayer(string layerName, ActivationSource source = ActivationSource.Script);
  • 作用域是当前配方，换产后上一个配方的图层名会被拒绝
  • 只认已生成轨迹的图层：轨迹一律由界面手动生成，这里拿不到就返回 false 且不触发事件，绝不顺手生成
  • 不写任何持久化数据，纯运行期指定，因此不带 async，也不会把工程标脏
  • 成功后触发 LayerActivated（带 RecipeCode、LayerName、Source），界面据此把轨迹区切到该图层

脚本拿到 false 就把该任务判为失败，由业务层定是报警还是跳过该图层

换产刷新与设置图层可能连着来。界面在换产刷新完成前收到图层激活会先挂起，等图层卡片重建完再切过去，避免切到还没渲染出来的图层上

回读当前状态

设置了什么就能读回什么，脚本不必自己再存一份，也方便回写给下位机：

读 对应的设置
DxfRecipeEntry? GetCurrentRecipe() SwitchRecipeAsync
string? GetCurrentLayer() ActivateLayer
TrajectoryPath? GetCurrentTrajectory() 当前配方 + 当前图层的轨迹，省掉自己拼编号与图层名

当前图层挂在配方工作区上，换产时工作区整个换掉，图层随之回到未激活，不存在跨配方残留。它只反映 ActivateLayer 设置的图层，界面手动点开某个图层的轨迹不会改变它——这里要回答的是"下位机在做哪个图层"，不是"操作员在看哪个图层"

点位下发

轨迹点与扩展点转成下位机可直接整段写入的定点整数：

// 六个位姿分量与点位类型各占一段连续数组
var buffer = trajectoryPath.ToPointBuffer(capacity: MAX_POINT_COUNT);
if (buffer.IsTruncated) {
    // 点数超出下位机点位区，判任务失败，不能只发一半就让设备走
}

await _mcProtocol.WriteWordsAsync("D", BASE_ADDR + 1650, buffer.X, token);
// ……Y / Z / Rx / Ry / Rz / Types 同理

// 单个扩展点按 X、Y、Z、Rx、Ry、Rz 顺序取六个整数，已叠加各自偏移量
await _mcProtocol.WriteWordsAsync("D", BASE_ADDR + 1616, extendedPoint.ToFixedPointPose(), token);
  • capacity 传下位机点位区的固定点数，多余位置补 0，下位机据此清掉上一层遗留的尾巴；传 0 则按实际点数分配
  • 默认取相对坐标、缩放 1000（毫米转微米、度转千分之一度），都可以改
  • 取整是先乘再四舍五入。反过来先按小数位取整再乘会踩二进制小数的坑：1.001 会变成 1000.999…，直接截断就少一个最小单位
  • 缩放后超出 32 位整数会抛 OverflowException，宁可失败也不能让数值回绕把设备开到错误位置

脚本运行与故障自恢复

现场通常只常显动态视图，没有人守在图纸导入页面上，所以脚本宿主对单次执行的失败不终止任务：

  • 周期任务里 StartAsync / CompleteAsync 抛出的异常被记录后，按 1、2、4……秒（上限 30 秒）退避重试，成功一次后恢复。只有点停止才会结束循环
  • 失败次数、最近一次错误记在 IDXFScriptService.Health，变化时触发 OnHealthChanged；每次启动重置
  • 已在运行、正在启动或停止时再调用 StartAsync 会抛 InvalidOperationException，不会起出第二个循环
  • 停止会先等循环收尾（最长 10 秒）再调用脚本的 StopAsync，不会与还在执行的 StartAsync 并发
  • 运行中手动「触发」单次执行，结束后回到原状态，不会把「运行中」误报为「已停止」
  • FixedIntervalMs = -1（脚本自管后台工作）时只调用一次 StartAsync，此模式下抛出的异常没有重试语义，仍按异常停止处理（OnTaskAbnormalStop）

脚本自己捕获并处理的异常不会进入 Health；希望被前端看到的故障，让它抛出来，或者用 DXFStatusReporter.Report 报告

状态上报

DXF 模块通过 DXFStatusReporter 定期上报运行状态、当前配方和图层信息，并通过发布委托写入目标位置。

发布目标由调用方决定，可以是动态视图结构体，也可以是 PLC、数据库等其他数据源。DXF 模块本身不依赖动态视图。

发布到动态视图时，结构体不用手工建：在数据中心点击「新建 → 从模块创建 → DXF 图纸导入」即可建出 DXF_Status（模块结构体，字段由 DXFStatusSnapshot 决定，不可编辑；应用升级新增字段后，工程打开时会自动追加）。

_statusReporter = new DXFStatusReporter(
    recipeRuntime,
    scriptService,
    (status, token) => statusPublisher.PublishAsync("DXF_Status", status, token));

_statusReporter.Start();   // 在脚本构造函数里启动，随脚本实例存在；重复调用无效果

_statusReporter.Report("SwitchRecipe", isOk, "配方不存在");

_statusReporter.Invalidate();

await _statusReporter.DisposeAsync();   // 只在脚本释放时（重新编译、应用退出）停止，会发布最后一次「已停止」
  • Start()：开始状态上报，重复调用不会重复启动
  • Report()：记录最近一次任务的执行结果
  • Invalidate()：状态相关数据发生变化后，使缓存数据重新读取
  • StopAsync() / DisposeAsync()：停止状态上报，并发布最终的停止状态。不要在脚本的 StopAsync 里调用：脚本停止后上报器应继续发布「已停止」和心跳，前端才分得清「已停止」与「模块离线」（心跳停止）

状态字段

DXFStatusSnapshot 的成员名称即对应的状态字段名称。内部结构体只需创建实际需要的字段。

分类 字段 类型 说明
运行 RunState Int16 运行状态：0 已停止、1 启动中、2 运行、3 停止中、4 编译中、5 处理中。
Heartbeat Int32 每次状态发布递增，可用于判断 DXF 模块是否持续运行。
UpdatedAt String 状态快照生成时间。
故障 IsFaulted Bool 是否处于故障重试状态。
ConsecutiveErrorCount / TotalErrorCount Int32 连续失败次数 / 累计失败次数。
LastError / LastErrorAt String 最近一次失败信息及时间。
最近任务 LastTask / LastTaskOk / LastTaskMessage / LastTaskAt String / Bool / String / String 最近一次任务及其执行结果，由 Report() 提供。
配方 RecipeCount Int32 配方总数。
RecipeCode / RecipeName String 当前配方，未激活配方时为空。
CalibrationRecipe / IsCalibrationExists / IsCalibration3D String / Bool / Bool 当前配方绑定的标定信息。
RecipeLayerCount / GeneratedLayerCount Int32 图层总数 / 已生成轨迹的图层数。
IsReady / ReadyReason Bool / String 是否具备运行条件及对应原因。原因代码包括 NoRecipe、NoCalibration、CalibrationMissing、NoTrajectory。
图层 Layer String 当前运行期激活的图层，未激活时为空。
IsLayerGenerated / IsLayerModified / IsLayerSimulated Bool 当前图层是否已生成轨迹、是否存在手动修改、是否已完成模拟确认。
LayerPointCount / LayerTotalLength / LayerUpdatedAt Int32 / Double / String 当前图层点数、轨迹总长度（毫米）及最后更新时间。
列表 RecipeListJson String 全部配方的 JSON 数组，包含 code、name、calibration、layerCount 和 generatedLayerCount。
Note

IsReady 用于判断基本运行条件：当前存在配方、绑定的标定存在，并且至少有一个图层已生成轨迹。

图层是否已模拟或被手动修改分别通过 IsLayerSimulated 和 IsLayerModified 判断，是否作为最终放行条件由现场业务决定。

配方列表

RecipeListJson 使用 JSON 数组保存配方列表，例如：

[
  {
    "code": "R001",
    "name": "产品 A",
    "calibration": "CAL001",
    "layerCount": 3,
    "generatedLayerCount": 3
  }
]

使用内部结构体承载该字段时，应为字符串字段预留足够长度，避免配方数量增加后 JSON 内容被截断

数据存储布局

工程根目录/
├── 工程名.masproj              # 配方索引 + 标定索引 + 脚本（工程级）
├── Calibrations/               # 标定数据，工程级共用，可被多个图纸配方绑定
└── Recipes/
    ├── R001/                   # 文件夹名 = 配方编号
    │   ├── layers/
    │   │   ├── 图层A.json      # 单图层完整 TrajectoryPath（含扩展点）
    │   │   └── 图层B.json
    │   ├── generations/        # 各图层的生成记录，供生产追溯
    │   └── parameters.json     # 该配方各图层的轨迹生成参数
    └── R002/
        └── ...

图层轨迹 JSON 以图层名命名（非法文件名字符替换为 _ 并追加 8 位哈希），文件内容的 Name 字段才是权威图层名
