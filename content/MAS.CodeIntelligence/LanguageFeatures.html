语言能力

本文说明补全、XML 文档注释、诊断与悬停四项能力的具体行为。四者共同遵循一条边界：

前端只判断"什么时候请求"，候选内容与声明结构一律由 Roslyn 给出。

编辑器页面里不出现任何硬编码的类型名、枚举值或标签名，语言知识全部留在 Worker 侧。

代码补全

触发时机

触发方式 场景
triggerCharacters: ['.', '<', '='] . 成员访问；< 泛型实参与文档注释标签；= 赋值与比较
onDidType 检测运算符后的空格 ==、!=、<=、>=、+=、&&、\|\|、??、=>、= 等之后输入空格，主动调用 editor.action.triggerSuggest
普通输入 Monaco 的 quick suggestions，延迟 300 毫秒，避免连续输入时每个字符都发一次请求

整行以 // 开头时不触发运算符补全。运算符补全只负责"弹出列表"，候选仍走同一个 csharp.completion 请求。

Worker 侧一律以 CompletionTrigger.Invoke 调用 Roslyn，不传入插入触发字符。Roslyn 在 Insertion 触发下会先用 ShouldTriggerCompletion 过滤 provider，= 这类字符可能把 provider 全部筛掉从而返回空列表；Invoke 等价于手动按 Ctrl+Space，各 provider 都会参与。

候选过滤与相关性排序

全局作用域一次补全 Roslyn 会返回一万条以上候选，全部回传会导致每次按键传输数 MB JSON。服务端按以下顺序处理：

  1. 按已输入前缀过滤：前缀匹配优先，其次首字母缩写匹配（dto → DateTimeOffset）。成员访问等前缀为空的场景不过滤；
  2. 按相关性排序：依据 Roslyn 的 MatchPriority 降序稳定排序；
  3. 截断到 300 条，被截断时结果标记 IsIncomplete，编辑器在后续输入时重新请求；
  4. 改写 SortText 为名次（"0000"、"0001"……），编辑器按它排序即可原样保留服务端排好的顺序。

MatchPriority 就是 Roslyn 表达类型推断的方式：它不减少候选，而是给目标类型匹配的符号加权。以 void M(bool flag, int count) 中的 if (flag == ) 为例：

候选 MatchPriority 说明
flag 600 类型匹配的局部变量/参数
Enabled 500 类型匹配的字段/属性
Equals、ReferenceEquals 400 返回类型匹配的方法
bool 200 类型匹配的关键字
枚举比较处的枚举类型 MatchPriority.Preselect 另见下节
count 及其余候选 0 与目标类型无关
nuint 等 -1 Roslyn 主动降权

如果跳过第 2、4 步而沿用 Roslyn 的字母序 SortText，flag、Enabled 会淹没在 Accessibility、async、await、base…… 之中，甚至被截断到 300 条之外——表现就是"运算符补全给一堆没用的候选"。

true / false 不被 Roslyn 加权，会落在字母序位置，这与 Visual Studio 的行为一致，不做额外的人工置顶。

预选候选

MatchPriority 达到 MatchPriority.Preselect 的候选（例如 if (day == ) 处的 System.DayOfWeek）会带上 IsPreselect，编辑器映射为 Monaco 的 preselect，列表弹出时默认高亮该项。

XML 文档注释

输入 /// 生成骨架

编辑器在 onDidType 中判断：本行光标前只有缩进加三个斜杠、光标后全是空白，才发起 csharp.documentationComment 请求。四个斜杠属于普通注释，不触发。

Worker 侧 DocumentationCommentGenerator 只做语法分析，不需要语义模型与元数据引用，也不占用补全队列。流程是：取光标右侧第一个记号，向上回溯到起点不早于光标的声明节点，再按声明类型产出标签。

声明 生成的标签
方法、局部函数、委托 summary + typeparam + param + returns（返回 void 时省略 returns）
构造函数 summary + param
运算符、转换运算符 summary + param + returns
索引器 summary + param
类型声明（含记录与主构造函数） summary + typeparam + param
其余声明，或光标后没有声明 仅 summary

不生成的情况：目标声明已经有文档注释（本行刚输入的 /// 不计入）、光标后仍有文本、四个斜杠。方法体内部输入 /// 只会得到 summary，不会误把外层方法的参数带进来。

返回结果里换行统一为 \n、续行不含缩进，由编辑器按模型自身的换行符与当前行缩进落地：优先使用 Monaco 的片段控制器 snippetController2（自动处理换行与缩进），不可用时退化为直接编辑并手工计算光标位置。

生成结果形如：

/// <summary>
/// |                                  ← 光标停在这里
/// </summary>
/// <param name="a"></param>
/// <param name="b"></param>
/// <returns></returns>
public int Add(int a, int b) => a + b;

文档注释内输入 <

< 属于补全触发字符，在文档注释中会走普通的补全请求，Roslyn 返回 summary、see、param name="a"、inheritdoc 等标签候选（param 候选带的是当前方法的真实参数名）。

Roslyn 给出的是光标前后两段文本（BeforeCaretText / AfterCaretText），服务端把它转成 LSP 片段，$0 标记插入后的光标位置，并用 IsSnippet 告知编辑器按片段插入：

候选 插入文本 落地效果
summary summary>$0</summary> <summary>❘</summary>
see see cref="$0"/> <see cref="❘"/>
param name="a" param name="a">$0</param> <param name="a">❘</param>

只给元素名的候选由服务端补出 > 与配对的结束标签；已经带 < 的候选，若光标前已有 < 则去掉重复的尖括号。字面量中的 $、\、} 会被转义，保证原样插入。

代码诊断

编辑器内容变化后防抖 600 毫秒发起一次 csharp.diagnostics，结果以 Monaco Marker 呈现，owner 为 csharp-roslyn。

只回传 Error 与 Warning 两级、且未被抑制的诊断。切换语言或切换 C# 语言服务开关时会先清除旧标记再重新调度一次：启用时补上标记，停用时只清除。

悬停信息

悬停由 Roslyn 的 QuickInfoService 提供，请求超时 3 秒。返回的内容块中，签名部分包装为 csharp 代码围栏，文档说明作为普通文本，编辑器按 Markdown 渲染。该位置没有符号时返回空结果，编辑器不显示悬停框。
