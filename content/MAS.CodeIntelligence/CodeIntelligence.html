C# 代码智能

代码编辑器中的 C# 补全、诊断、悬停与 XML 文档注释统称为「C# 代码智能」，由一个基于 Roslyn 的独立后台进程 MAS.CSharpWorker 提供，主程序通过命名管道与其通讯。

在应用程序设置的「高级」页有 C# 语言服务 开关（IsCSharpLanguageServiceEnabled）。开关关闭时不启动 Worker 进程，编辑器页面也不会发出任何请求。

为什么是独立进程

Roslyn 分析内存代码需要把数百个元数据引用读进内存，全局作用域一次补全会产生上万条候选，编辑器连续输入时还会不断产生新的编译快照。这些内存放在主程序进程里既无法及时归还操作系统，也会把主程序的 GC 压力抬高。

放进独立进程后：

  • 主程序进程的内存占用不受 Roslyn 影响；
  • 编辑器全部关闭时可以让 Worker 做一次压缩式回收，把内存还给操作系统；
  • Worker 崩溃只会让补全失效，不会影响主程序。

参与的项目

项目 职责
MAS.Monaco 编辑器页面与 MonacoService。前端判断"何时请求"，后端负责转发与回传
MAS.SharedLibrary ICodeCompletionService 服务接口与 ICodeCompletionOptions 开关接口
MAS.Compilation CodeCompletionProxyService（作用域服务）与 CSharpWorkerHost（进程级单例），负责拉起进程与转发请求
MAS.CompilationContracts 主程序与 Worker 共用的请求/结果模型和 IPC 方法名常量
MAS.CSharpWorker Worker 进程：CSharpLanguageService 承载 Roslyn 工作区，DocumentationCommentGenerator 生成注释骨架
MAS.NamedPipeIpc 命名管道 IPC 的服务端与客户端

调用链路

Monaco 编辑器页面 (editorFunctions.js)
  │  postMessage: CompletionRequest / DiagnosticsRequest
  │               HoverRequest / DocumentationCommentRequest
  ▼
MonacoService                      每类请求各持一个 CancellationTokenSource
  │                                新请求取消旧请求，只回传最新请求的结果
  ▼
ICodeCompletionService
  └─ CodeCompletionProxyService    编辑器窗口级作用域，Attach/Detach 计数
       ▼
     ICSharpWorkerHost
       └─ CSharpWorkerHost         进程级单例：按需拉起 Worker、维护可用性
            │  命名管道 MAS.CSharpWorker.{主程序进程号}
            ▼
          CSharpWorkerHostedService
            └─ CSharpLanguageService (Roslyn AdhocWorkspace)

主程序侧对每类请求只保留最后一次；Worker 侧的补全、诊断、悬停各有一个抢占队列（SupersedingRequestQueue），新请求到达即取消正在执行的旧请求，避免连续输入时堆积数十个并发的 Roslyn 分析。

进程生命周期

阶段 行为
启动 首个编辑器窗口打开时 CSharpWorkerHost 先 ping 管道，无响应才启动 MAS.CSharpWorker.exe，等待就绪最长 30 秒
启动参数 --pipe <管道名> --parent-pid <主程序进程号> --log <日志目录>，日志写入默认日志路径下的 CSharpWorker 子目录
初始化 收集元数据引用、创建 Roslyn 工作区，并执行一次补全预热，随后状态置为 Ready
空闲 每 5 秒检查一次，超过 10 秒没有请求就回收一次临时内存
编辑器全部关闭 DetachClient 计数归零时发送 csharp.trim，Worker 清空文档内容并做一次压缩式 GC；基础引用保留，无需重新初始化
主程序退出 OnExit 中发送 csharp.shutdown，1.5 秒内未退出则强制结束；此外 Worker 自身也监视父进程，父进程消失即退出

可用性状态

CodeCompletionAvailability 同时用于 Worker 内部、CSharpWorkerHost 与代理服务，状态变化通过 AvailabilityChanged 事件通知界面（编辑器状态栏显示"补全未启用"等文案）。

状态 含义
Initializing 正在收集引用、创建工作区与预热
Ready 可用；只有该状态下才会真正转发请求
Unavailable 初始化失败、Worker 进程已退出或服务已释放
Disabled 设置中的开关未启用，不会启动进程

元数据引用

Worker 的编译引用由三部分合并去重（按文件路径）后交给 Roslyn：

  1. 基础引用：主程序部署目录下的托管 *.dll，加上主程序传来的可信平台程序集（TPA）列表。仅在初始化时收集一次；
  2. 动态程序集：主程序内存编译产物，随请求同步（见下）；
  3. 请求级引用：请求携带的 ReferencePaths 与 ReferenceDirectories（目录会递归扫描 *.dll）。

创建引用时若同目录存在同名 .xml 文档文件，会一并加载为 XmlDocumentationProvider，因此补全与悬停能显示 XML 文档说明。

动态程序集同步

主程序内存中编译出来的程序集没有磁盘文件，Worker 拿不到，需要按请求把字节传过去。

  • 主程序侧 DynamicAssemblySynchronizer 以字节数组的引用标识判断版本，只在程序集实际变化时才传字节；同步状态在 Worker 确认（请求成功返回）后才提交，请求失败或被取消时下次重传。
  • Worker 侧 DynamicAssemblyCache 按版本合并字节，并依据请求携带的单调递增序号淘汰已卸载的程序集。乱序到达时：字节始终按版本合并，淘汰只认最新序号的快照，避免旧快照误删刚同步进来的程序集。

编译选项

Worker 的工作区使用 LanguageVersion.Latest 解析，并启用可空引用类型上下文（NullableContextOptions.Enable）。启用可空上下文是为了让编辑器诊断与主程序工程保持一致，否则代码里的 ? 注解会报 CS8632。
