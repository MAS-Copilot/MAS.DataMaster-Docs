协议与契约

代码智能有两段协议：编辑器页面与 MonacoService 之间的 WebView 消息，以及主程序与 Worker 之间的命名管道 IPC。

WebView 消息

前端发往后端

前端通过 window.chrome.webview.postMessage 发送，MonacoService.OnWebMessageReceived 按 type 分发。所有请求都带 requestId，后端只回传最新一次请求的结果。

消息类型 数据模型 触发时机
CompletionRequest CompletionRequestMessage 触发字符、运算符后空格或 quick suggestions
DiagnosticsRequest DiagnosticsRequestMessage 内容变化后防抖 600 毫秒
HoverRequest HoverRequestMessage 鼠标悬停
DocumentationCommentRequest DocumentationCommentRequestMessage 输入 ///

除诊断请求只带 code 外，其余都带 code 与 position（字符偏移，从 0 开始）。

后端回传前端

后端通过 ExecuteScriptAsync 调用页面上的全局函数。

前端函数 载荷字段
deliverCompletions requestId、replaceStart、replaceLength、items[]
deliverDiagnostics requestId、diagnostics[]（id、message、severity、start、length）
deliverHover requestId、found、start、length、contents[]
deliverDocumentationComment requestId、found、text、caretOffset
refreshCsharpDiagnostics 无。切换开关后清除并重新调度一次诊断

另有一个全局开关变量 window.__masCodeIntelligenceEnabled，由 SetCodeCompletionEnabled 写入。为 false 时前端不发出任何代码智能请求。

前端收到回包后仍会做一次校验：请求号必须是最新的、模型语言仍是 csharp；文档注释还会额外确认光标依旧停在 /// 之后，否则丢弃，避免用户已经继续输入时被插入内容。

Worker IPC 方法

方法名常量定义在 CSharpWorkerMethods，管道名为 MAS.CSharpWorker.{主程序进程号}，多开主程序互不干扰。

方法 请求 响应
ipc.ping — "pong"
csharp.initialize CSharpWorkerInitializeRequest CSharpWorkerStatusResponse
csharp.status — CSharpWorkerStatusResponse
csharp.completion CSharpWorkerCompletionRequest CodeCompletionResult
csharp.diagnostics CSharpWorkerDiagnosticsRequest CodeDiagnosticsResult
csharp.hover CSharpWorkerHoverRequest CSharpWorkerHoverResponse
csharp.documentationComment CSharpWorkerDocumentationCommentRequest CSharpWorkerDocumentationCommentResponse
csharp.trim — bool。最后一个编辑器窗口关闭时回收临时内存
csharp.shutdown — bool。主程序退出时请求 Worker 结束

四个语言请求的外层类型都继承 CSharpWorkerRequestBase，携带动态程序集同步信息：

字段 说明
SyncSequence 主程序单调递增的同步序号，Worker 只依据最新序号执行淘汰
Assemblies 本次需要传输的程序集字节，仅包含 Worker 尚未确认收到的版本
AssemblyNames 当前全部动态程序集名称，Worker 据此淘汰已卸载的缓存

数据模型

模型都在 MAS.CompilationContracts，主程序与 Worker 共用。

CodeCompletionResult

字段 说明
Items 候选集合，最多 300 条
ReplaceStart / ReplaceLength 替换范围，编辑器据此计算插入区间
IsIncomplete 候选被截断，编辑器需在后续输入时重新请求（Monaco 的 incomplete 语义）

CodeCompletionItem

字段 说明
Label 显示文本
InsertText 实际插入文本；IsSnippet 为 true 时是含 $0 的 LSP 片段
Kind 类别标签，取自 Roslyn 的首个 Tag，前端映射为 Monaco 的图标类型
SortText 服务端排好的相关性名次，编辑器直接按它排序
FilterText 过滤文本
IsSnippet 按片段插入，字面量中的 $、\、} 已转义
IsPreselect 预选候选，编辑器默认高亮

DocumentationCommentRequest / DocumentationCommentResult

请求只有 Code 与 Position：骨架生成只依赖语法树，不需要程序集引用。

结果中 Text 为要在光标处插入的文本，换行一律 \n 且续行不含缩进；CaretOffset 是插入后光标相对文本起点的偏移。该位置不应生成注释时整个结果为 null（回包中 found 为 false）。

其余模型

CodeCompletionRequest、CodeDiagnosticsRequest、CodeHoverRequest 都带 Code、ReferencePaths、ReferenceDirectories，除诊断外还带 Position。CodeDiagnosticsResult 与 CodeHoverResult 分别承载诊断列表与悬停内容块。

扩展一项新能力

新增一项语言能力需要按顺序改动六处：

  1. MAS.CompilationContracts：请求/结果模型、Worker 请求与响应模型、CSharpWorkerMethods 方法名；
  2. MAS.CSharpWorker：在 CSharpLanguageService 上实现，并在 CSharpWorkerHostedService.RegisterLanguageHandlers 注册处理器；
  3. MAS.Compilation：ICSharpWorkerHost 与 CSharpWorkerHost 增加转发方法；
  4. MAS.SharedLibrary：ICodeCompletionService 增加接口方法；
  5. MAS.Compilation：CodeCompletionProxyService 实现代理；
  6. MAS.Monaco：消息模型、MonacoService 的分发与回传，以及 editorFunctions.js 的触发与落地。

单元测试位于 tests/MAS.CSharpWorkerUnitTest，通过 LanguageServiceFactory 以测试进程自身的部署目录与 TPA 构造已初始化的语言服务，等价于 Worker 收到主程序的初始化参数。
