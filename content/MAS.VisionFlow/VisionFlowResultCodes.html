VisionFlow 管道结果码约定

结果结构

节点具体结果见节点结果码约定

编号 枚举项 含义与运行处置
0 Unknown 未分类或未知；不按成功或可以继续处理
1000 Success 选中路径正常完成，允许条件分支跳过；处理结果、执行完成回调后继续
2000 NoResult 必要业务结果缺失；依赖分支跳过，处理结果、执行完成回调后继续
2001 JudgementFailed 有效数据判定 NG；保留测量，处理结果、执行完成回调后继续
3000 Faulted 运行故障；交付故障结果后停止，不调用完成回调
4000 Cancelled 主动取消，未形成完整业务结果；不伪造 NG 或确认完成

Success 不代表工件已经经过合格判定，采样或示教流程也可以正常完成

汇总与来源

  • 节点码通过显式映射汇总，不能强制转换或按数值大小排序。
  • 优先级为：已知运行故障、取消、未知结果、必要业务无结果、判定 NG、正常成功。
  • 同类多个根因按本轮执行计划的拓扑顺序选取，避免结果受并行完成顺序影响。
  • SourceNodeId 指向主原因节点。Nodes 保留各节点的具体结果码、说明和本轮数据；依赖跳过的节点保留原始来源。
  • 条件未选中及其依赖跳过汇总为 Success，不因此产生业务无结果；其他实际执行分支报告的无结果或 NG 仍然保留。
  • 多端口节点的原图、空列表等可以继续有效。只有连接到缺失业务输出的消费者跳过，不把整个定位节点的全部下游都跳过。

同一轮同时出现 NoResult 与 JudgementFailed 时，汇总为 NoResult，表示必要检测数据不完整；不是把该轮视为合格。NG 节点的结果码及有效测量仍保存在 Nodes 中，需要统计全部不合格原因时应遍历节点结果，不能只比较管道码是否等于 JudgementFailed。IsCompleted() 仅表示允许进入正常结果处理和完成回调

连续运行和脚本

成功、业务无结果、判定 NG 均走 HandleResultAsync → CompleteAsync → 下一轮。运行器使用 ResultCode.IsCompleted() 统一分类，不能把“不是 Success”当作停机条件。

public async Task HandleResultAsync(VisionRunResult result, CancellationToken token = default) {
    switch (result.ResultCode) {
        case VisionRunResultCode.Success:
            // 按本轮有效业务数据回写正常结果
            break;
        case VisionRunResultCode.NoResult:
        case VisionRunResultCode.JudgementFailed:
            // 回写未找到或 NG，不发送无效坐标
            break;
        case VisionRunResultCode.Faulted:
            // 回写故障，运行器随后停止
            break;
        default:
            // 未识别结果不得默认放行
            break;
    }
}

CompleteAsync 只在业务结果处理正常返回后调用。结果处理或完成回调失败仍停止循环，不能在 finally 中无条件确认完成。故障结果保留原有带期限的独立交付令牌，避免相机故障直接取消故障回写。

脚本试跑与连续运行采用相同分类。回调应读取传入的本轮结果：result.GetNodeResultCode("定位")、result.GetNode("定位") 或已有的安全取值方法。

拒绝与取消

  • 管道已连续运行时，额外触发或运行到节点抛出 VisionPipelineBusyException，不产生假的工件检测结果，也不影响原循环。
  • 无效管道或已删除节点沿用入口异常契约，不放入执行结果码。
  • 主动取消保留 OperationCanceledException 契约，不保证向脚本交付一份 Cancelled 结果；实际被取消的节点标记取消，未到达节点清除旧结果状态，不确认本轮正常完成。
  • 相机明确断线时，故障结果包含已知来源节点及 DeviceError，不被随后发生的取消覆盖。

界面与发布

管道统计使用 LastResultCode。Web 发布帧和 Web SDK 使用数值 resultCode；SDK 将 NoResult 和 JudgementFailed 显示为 NG，将故障等显示为异常。

条件未选中的发布分支不发帧；业务无结果导致发布节点被跳过时仍发布本轮状态，不把上一轮图像冒充为本轮图像。有效分支的测量和图像仍按现有生命周期管理。

验证

核心回归包括：正常 → 未找到 → 正常的不中断交付、条件跳过仍成功、有效分支继续、NG 测量可读、旧坐标失效、并行故障来源稳定、真实设备故障仍停止，以及 Web 状态和图像更新。
